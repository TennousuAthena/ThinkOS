# 32 · 开放界面：系统 UI 与组件也是插件

> 2026-11-02，策划稿，ADR-039。**方向是用户定的；机制是我的提议，可以推翻。** 没有写代码，没有上设备验证。
> 标记：**已核对** = 读过代码或跑过脚本；**提议** = 我的设计；**未验证** = 开工前要上真机。
> 先读：`AGENTS.md` → ADR-013 / 015 / 016 / 017 / 029 / 033 → `06-plugins.md` §4、§6、§11 → `29-panel-and-apps.md` → 本文。

## 1. 设计目的

> 任何插件均平等，系统默认 UI 和组件也是 Lua 插件实现，用户可以替换为自己想要的任何内容。——用户，2026-11-02

拆成三条可以检验的要求：

| | 要求 | 怎么检验 |
|---|---|---|
| E1 | **平等**：没有只有内置插件才能走的路——同一套 `tos.*`、同一套权限检查、同一套安装 / 升级 / 回滚 | 把任何一个出厂插件换成别人写的，宿主代码一行不改 |
| E2 | **界面也是插件**：页面、版式、组件（时钟、列表、滑块、音乐界面、电视界面、磁贴、操作栏……）都由 Lua 插件实现，APK 里只剩机制 | `ui/` 里不再有“某个具体组件长什么样”的代码 |
| E3 | **可替换**：用户选择哪个插件提供哪个页面 / 版式 / 组件，随时可以换回出厂；换坏了会自己退回去 | 在设备上换掉时钟表盘的提供方，其它插件不受影响，重启后保留 |

同时必须保住的（已有的硬约束和用户的优先级）：Lua 不在主线程；**时钟秒级精度最高优先**（ADR-029）；设备自主（ADR-015）；恢复路径不依赖插件；只能 armv7 / API 27，不用 WebView 和 Compose；内存峰值 < 350MB，冷启动 < 3s。

## 3. 现状离目标有多远（已核对）

### 3.1 平等性审计

好消息：E1 在文档里早就有——`06-plugins.md` §10 写着“如果某个自带功能用这套接口做不出来，说明运行时缺能力，应该补运行时，而不是给它开后门”。我把宿主里所有 `system.` 和 `factory` 的出现位置查了一遍，**插件接口本身基本平等**：`host()` 里除 `system.*` 之外没有给内置插件单开的方法。不平等集中在下面几处：

| # | 不平等之处 | 位置 | 目标 |
|---|---|---|---|
| 1 | `system.*` 只授予“摘要与 APK 内置副本相同”的插件 | `PluginRuntime.kt:197`（`grantedPermissions`）、`:922`–`:929`（`requireSystem`、`requireSettingsAdmin`） | 强权限，设备上确认后可授予任何插件；出厂授权写进同一份授权表（§5.2） |
| 2 | 控制面板角色只认持有 `system.device` 的内置版本；安装时另有一套检查 | `PluginRuntime.kt:790`、`:754`–`:760` | 角色由绑定表决定（§4.2） |
| 3 | 角色“先到先得”：`pages.firstOrNull { role in it.roles }`，候选按 home、sleep、其它排，再按页面键字母序，用户没有选择权 | `DeckRouter.kt:30,36,56,81,121,175,218,220`；`PluginRuntime.kt:791` | 用户可选的绑定表，多个候选时不靠字母序 |
| 4 | 安全模式只启动 id 为 `clock` 的出厂插件 | `PluginRuntime.kt:303`、`:355` | 安全模式 = 只用出厂绑定，不写死 id |
| 5 | 设置插件固定安装、不可卸载，Git 包不得顶替它（文档规则；设备端目前靠 #1 实现） | `06-plugins.md` §11.3、§12.6 | 可替换；管理接口 `tos.settings.*` 由 `system.settings` 授权 |
| 6 | **词汇只有 APK 能扩展**——这是最大的一处 | 组件：`PageView.kt:121`–`:139`（`when (type)` 兜底）、`BuiltinComponents.kt:28`、`RuntimeHost.kt:151`–`:156`（三家工厂）；版式：`PageView.kt:522,528,582,794,822` | 契约与提供方（§4.2–4.3） |

### 3.2 词汇审计

- `layouts.json` 的 `x-thinkos-api`：**20 种组件、8 种版式、2 种卡片模板**，对应 `ui/` 里 10,251 行 Kotlin。
- 组件由 4 处工厂创建（`BuiltinComponents`、`DeviceComponents`、`MediaComponents`、`ImageComponents`），外加 `ComponentGroup.update` 里的 `when (type)` 兜底。
- 版式不是数据驱动的，是 `PageView` 里的代码路径：`tiles` / `aero` / `panel` / `stage` 各有专属分支、几何计算（`RenderGeometry`、`PanelGeometry`）和手势特例。
- 组件与舞台之间的接缝 `RenderComponent` 有 20 个成员。除了绘制和绑定，还有**手势仲裁**（`interactiveAt`、`capturesHorizontalAt`、`dragVertical…`）、**防烧屏**（`burnInOffset`）、**帧调度**（`animating`、`tick`）。插件提供的组件必须能用声明表达这些，这是场景内核设计的主要约束（§4.3）。
- 写进组件里的“好看”和性能技巧：磁贴入场与倾斜按压、翻面调度、天气图标图集缓存、Aero 静态窗口的后台栅格化、栈翻页时的圆角离屏蒙版。迁移时最容易丢的就是这些（§5.1）。
- 已声明未实现的词汇：`grid`（API 8 契约里有，**没有渲染器**，`plugins/apps` 也还没写）。所以现在冻结原生词汇的代价为零。

## 4. 目标架构（提议）

### 4.1 分层

```
┌─ 用户层：全是插件，全部可替换 ─────────────────────────────────────────┐
│ 页面与角色：home  settings  panel  apps  clock  weather  player  iptv …   │
│ 组件库：    clock  list  slider  nowplaying  tv  tabs  chart  progress …   │
│ 版式库：    stacks  focus  split  stage  tiles  aero  panel  form          │
│ 出厂集合 = 随 APK 内置、预先装好、预先授权的一组插件，和别的插件同类       │
├─ 场景内核（原生，只有机制，不含任何具体长相）───────────────────────────┤
│ 场景树 · 绘制原语 · 信号与表达式 · 属性动画 · 手势 · 文字 / 图片 / 视频面  │
│ 契约与绑定解析 · 场景快照                                                   │
├─ 运行时与能力服务（原生，只经 tos.* 与权限）─────────────────────────────┤
│ Lua 运行时 / 沙箱 / 预算 · 设置 · 媒体 · 投屏 · 传感器 · 设备 · 网络 · 存储 · 时间 │
├─ 内核外壳（原生，不可替换）─────────────────────────────────────────────┤
│ 救援菜单 · 安全模式 · 出厂恢复 · 权限确认框                               │
│ 夜间滤镜 · 防烧屏 · 亮度与注意力策略 · 帧率档位（对所有插件一视同仁）     │
└────────────────────────────────────────────────────────────────────────┘
```

三条原则：

- **机制归内核，长相归插件。** 内核知道怎么画圆角矩形、怎么跟手，不知道什么是“时钟”。
- **反馈在原生，决策在 Lua。** 按下反馈、跟手拖动、翻页弹簧、滚动、时间驱动的运动都由内核完成；Lua 只回答“显示什么”“点了之后做什么”。这条同时守住“Lua 不进主线程”和“时钟优先”。
- **平等 = 同一个检查。** 出厂插件和别人的插件走同一段代码，差别只是初始状态（已安装、已授权）。

### 4.2 契约与提供方

- **契约**：有名字、有主版本的接口。三种：`role/<名>`（整页角色：home、ambient、sleep、settings、panel）、`layout/<名>`、`component/<名>`。定义放 `shared/schema/contracts/`（提议），含 props 的模式、会发出的事件、槽位、需要的权限。今天的 20 + 8 + 2 个词汇就是第一批契约，旧插件写的 `{"type":"clock"}`、`"layout":"tiles"` 不用改。
- **提供方**：manifest 里用 `provides` 声明自己实现了哪些契约。
- **绑定**：契约 → 提供方，存在系统设置 `ui.bindings`（走 `SettingsStore`，ADR-017），默认值就是出厂集合。设置界面（也是插件）列出每个契约的可选提供方。
- **解析顺序**：用户绑定且健康 → 出厂提供方 → 内核占位（一个看得见的“此组件不可用”方块，不崩溃、不黑屏）。
- **组件是粗颗粒的**：一个 `clock`、一个 `nowplaying`，不是列表里的一行。行用声明式模板由内核原生绑定，不会每行调一次 Lua。
- **使用方只传 props、收事件**，看不到提供方的内部（和 `exports/uses`（ADR-027）一样默认私有）。数据层的 `exports` / `uses` / `calls` 不变。
- **版本**：暂定 API 9 引入 `provides`、`tos.ui`、场景视图；API 1–8 的插件由出厂提供方继续服务，一行不用改。

manifest 示意（接口没定，不是契约）：

```jsonc
{ "id": "my-clock", "api": 9, "main": "main.lua",
  "provides": [
    { "contract": "component/clock@1", "entry": "components/clock.lua" },
    { "contract": "role/sleep@1",      "page":  "face" } ] }
```

### 4.3 场景内核

**绘制原语**（留在原生，因为它们碰系统资源或者性能技巧很重）：

| 类 | 原语 | 说明 |
|---|---|---|
| 结构 | `group` | 平移 / 缩放 / 旋转 / 透明度 / 裁剪 / 硬件层提示；排布 `row` `column` `stack` `absolute`，带权重、间距、对齐 |
| 图形 | `rect`（含圆角）`circle` `arc` `line` `path` | 填充 / 描边 / 渐变；**不提供模糊和大面积阴影**（`04-ui-spec.md` §6） |
| 文字 | `text` | 字号档、字重、对齐、行数、自动缩放、省略；断行、RTL、字形交给系统排版 |
| 图 | `image` `icon` | 来源与解码沿用 ADR-024（OS 管授权、缓存、采样）；`icon` 按名字取 OS 图标集，天气图标图集缓存留在这里，不让每个提供方各写一份 |
| 面 | `video` | `MediaEngine` 的画面面；需要 `media` 权限 |
| 滚动 | `scroll` | 虚拟化列表，行是声明式模板，原生绑定字段 |
| 挂载 | `slot` | 放另一个提供方的组件（契约 + props） |

按这个分法，今天的 20 种组件里 `text` `icon` `image` `video` 是原语，其余 16 种（clock、form、progress、chart、list、daylight、moon、carousel、controls、seekbar、nowplaying、tv、tabs、slider、toggle、grid）加 8 种版式、2 种模板，共约 **26 个提供方**要用 Lua 改写。

**信号**：内核提供、只读、会自己变的值。

| 信号 | 内容 |
|---|---|
| `time` | 已对时的墙钟、`hour12` `minute` `second` `second_f`、命名格式化文本（`@time` 等，跟随系统语言与 12/24 小时） |
| `screen` | 宽、高、密度、方向、RTL |
| `theme` | 颜色令牌（主色、次色、强调、分隔、表面）与明暗 |
| `attention` | ASLEEP / AMBIENT / AWAKE / ENGAGED |
| `media` | 状态、位置、时长、缓冲（沿用保留键 `media`） |
| `device` | 亮度、音量（需 `system.device`） |
| 手势量 | 每个节点的 `press`、`drag.x/y`、`drag.velocity`、`scroll.offset` |

**表达式**：节点属性可以绑定一个纯数值表达式，输入是信号和 props，在原生里求值，输入变了才重算。运算只有四则、取模、`min` `max` `clamp` `lerp` `smoothstep` `sin` `cos` `floor` 和 `select(条件, a, b)`，每个属性 ≤ 64 个运算（提议），没有循环和函数，所以代价有界、算进场景预算。这和 `Binding` 的“不支持表达式”不矛盾：那是**状态**绑定，逻辑留在 Lua；这里是**每帧**的数值绑定，必须留在原生。

**动画**：属性可以声明 `transition`（时长 + 曲线或弹簧）；改属性时由内核做过渡，Lua 不用管每一帧。线性的时间驱动旋转（扫秒）编成 RenderThread 上的属性动画，沿用 Aero 模拟钟已经在用的做法。

**手势**：节点声明 `tap` / `long` / `drag{轴, 范围, 吸附点, 弹簧}` / `scroll`，识别和跟手在原生；产生信号（偏移、速度、进度）和少量离散事件（`tap`、`drag.end`、`snap`）发给 Lua。`claim` 声明取代今天的 `capturesHorizontalAt` / `interactiveAt`，让舞台知道这一块不要拿去翻页。翻页、变体、长按进设置、顶部下拉、救援手势仍然在舞台层（原生），先于插件画的任何东西。

**预算（提议）**：每个插件 ≤ 600 个节点；提交合并 50 ms（同 `tos.state.set`），持续 ≤ 8 次 / 秒；场景表的内存算进每插件 4 MiB；**不提供 `onFrame`**。

**快照**：每页最后一次提交的场景存盘（沿用 `03-architecture.md` §3.13 “最后画面快照”的设计，存场景而不是位图），冷启动先由内核直接画出，Lua 起来后再对账——冷启动不依赖任何 Lua。**未验证。**

**落到 API 27 上**：有动画的 `group` 用真正的 `View`（位移、缩放、旋转、透明度在 RenderThread 上做，不占主线程）；静态的叶子节点批在同一个 `View` 里一次画完并缓存。API 27 没有公开的 `RenderNode`（API 29 才有），所以不走那条路。**未验证。**

### 4.4 一个例子：时钟

```lua
-- components/clock.lua（示意）
local ui = tos.ui
return function(props)
  if props.style == "analog" then
    return ui.group{ aspect = 1, children = {
      ui.circle{ stroke = "theme.divider", stroke_width = 2 },
      ui.line{ to = {0, -0.50}, rotate = "time.hour12 * 30 + time.minute * 0.5" },
      ui.line{ to = {0, -0.80}, rotate = "time.minute * 6 + time.second * 0.1" },
      ui.line{ to = {0, -0.90}, rotate = "time.second_f * 6", stroke = "theme.accent" },
    } }
  end
  return ui.text{ value = "time.format('@time')", style = "display" }
end
```

引号里是信号表达式，由内核求值。Lua 只在挂载和 props 变化时跑一次；指针怎么走、数字什么时候换，Lua 不参与。所以**这个时钟的迟到只取决于内核，和今天一样**——这是设计目的与“时钟优先”能同时成立的关键。

## 5. 三个难点

### 5.1 性能与“时钟优先”

- **为什么不让 Lua 每帧画**：所有插件的 Lua 共用一个插件线程（`03-architecture.md` §3.7.2），单次最长 50 ms；A53 上每帧调一次 Lua，会同时拖垮时钟和翻页。
- **办法**：信号 + 表达式 + 属性动画。运动在原生，Lua 提交一次场景。
- **要保住的技巧**（§3.2 的清单）：做成内核原语（`icon` 的图集、`scroll` 的虚拟化、手势里的弹簧），不是每个提供方各写一份。
- **所有提供方共线程的代价**：UI 提供方的 Lua 和数据插件共用一个线程，一个重的数据插件（`iptv` 实测最长一片约 23 ms）会让界面**更新**晚一点，但**反馈**不受影响，因为反馈在原生。如果实测不够，再考虑给 UI 提供方单独的线程（**未验证**）。
- **验收口径**：见 §6.1。

### 5.2 信任与强权限

“平等”意味着 `system.*` 不能再是“APK 内置专属”，否则替换版的设置页、操作栏永远做不出来。同时它们能改 Wi-Fi、亮度、设置、启动安卓 App，不能随便给。

| 档 | 例子 | 怎么授予 |
|---|---|---|
| 普通 | `network` `media` `library` `location` `presence` | 沿用现状（M2 起由 Server 上确认，见 `06-plugins.md` §12.6） |
| **强** | `system.settings` `system.device` `system.apps` | **必须在设备上确认**：原生对话框，插件画不出来也代答不了；绑定到摘要，换了摘要要重新确认；出厂版本在首次启动 / APK 升级时由内核**播种**进同一份授权表 |
| 内核专有 | root 守护进程命令、原生代码、绕过沙箱 | 不可授予；仍然只经 `system/` 模块的窄接口（ADR-033） |

确认框写明：插件名、来源（Git 地址加 commit，或“本机目录”）、摘要前 12 位、逐项用人话列出的强权限（“可以改亮度、音量、Wi-Fi”）、它要取代的契约。只接受屏幕上的触摸确认——Server 和远程指令都不能代点。授权可以在救援菜单撤销。

出厂预授权**不是特权**：代码里不再有 `factory[id]?.digest == digest` 这种判断，只有“授权表里有没有这一条”。

已知并接受的风险：全屏的角色提供方可以在自己的页面里画一个假的“系统对话框”。设备上没有个人账号，Wi-Fi 密码是在安卓设置页里输入的，所以损失有限；真正的确认框和救援菜单是原生的，插件盖不住它们。

### 5.3 恢复

“换成任何内容”意味着有人会换坏。恢复路径仍然不依赖插件（`06-plugins.md` §11.3 的原则）：

- 原生救援菜单（左上角双指长按 5 秒，在舞台层，先于任何插件）新增“界面：恢复出厂绑定”。
- **安全模式 = 只用出厂绑定和出厂集合**，忽略 `ui.bindings`，不再写死 `clock`。
- **自动回退**：绑定的提供方连续崩溃（沿用 `PluginHealth` 的退避）、挂载后 5 秒内没有提交过非空场景、或被隔离，内核换回上一个健康的绑定并记日志。
- 调试包加 `scene_dump` 命令，输出场景树、信号和预算占用，写进设备测试脚本。

## 6. 迁移（绞杀者模式）

原则：**旧的原生实现不动，直到对应的 Lua 提供方通过验收才删**；API 1–8 的插件一行不用改。以下“大小”是相对的，不是日历。

| 阶段 | 内容 | 大小 | 验收 |
|---|---|---|---|

### 6.1 S1 的门槛与止损

门槛是**提议**，目的是在花大力气之前确认方向走得通：

| 项 | 门槛 | 怎么量 |
|---|---|---|
| 时钟 | ADR-029 的全部判据**不放宽**：连续 60 秒换秒 p95 ≤ 40 ms、最大 ≤ 80 ms、不漏秒；与对时服务器偏差 ≤ 100 ms；主线程停 700 ms 后立刻显示真实的秒 | `tools/tests/clock_accuracy_device.py` 对 Lua 版时钟页 |
| 待机 | AWAKE 静态数字时钟与 AMBIENT 首页的单核 CPU 不超过 `13-pre-m1-hardening.md` 基线的 +20%，janky < 5% | `bench.sh` / `gfxinfo`（跑之前先告诉用户） |
| 滑块 | 手指到像素不经过 Lua（让一个插件占满 50 ms 切片时拖动仍然跟手）；松手后的 `change` 事件 ≤ 100 ms 到达 Lua | 设备脚本 |
| 内存 | 出厂 UI 库常驻 Lua 内存 < 3 MiB，PSS 增量 < 10 MB | `dumpsys meminfo` |
| 冷启动 | 仍 < 3s（断网、无 Server） | `pre_m1_cold_start.py` |

**止损**：时钟或待机一项做不到，调优一轮后仍不达标——不做“Lua 自绘”，退回 P2 的终点：提供方可以替换高层组件和版式（用现有原语组合），绘制原语（时钟表盘等）仍是内核的固定词汇。那时 E2 只能做到一半，我会把丢掉的部分交还用户决定，不会悄悄降标准。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 性能不达标，尤其时钟 | S1 先行；反馈在原生；止损线（§6.1） |
| 工作量大（约 26 个提供方 + 一个小型 UI 框架） | 分阶段；旧实现保留到新实现过关；P4 可并行 |

| 12 个现有插件用旧词汇 | 旧词汇由出厂提供方继续服务，API 1–8 不动 |
| 没有文档和校验器，作者（包括 AI）写不对 | P3 的交付物包含 `shared/schema/`、示例提供方、打包器校验、`scene_dump` |

## 8. 要用户定的事

1. **强权限**：从网络（Server / Git）装来的插件，能不能拿到 `system.*`（改 Wi-Fi、亮度、设置、启动安卓 App）？*推荐：能，但必须在设备上点确认，每次换摘要重新确认。*
2. **“任何内容”的边界**：翻页范式、手势映射这层外壳要不要也开放（P5）？*推荐：先不开放，P4 做完再看；救援菜单、安全模式、夜间滤镜、防烧屏、亮度与注意力策略永远是内核。*
3. **性能口径**：重写后的出厂组件必须不差于原生（CPU / 掉帧 / 内存 +20% 容差，时钟度量不放宽）？*推荐：是；做不到的地方把能力提成内核原语，而不是降标准。*
4. **词汇冻结**：API 8 之后不再往 APK 里加新的原生组件和版式？*推荐：冻结；先把 API 8 这批（ADR-035 到 038）收口提交。*
