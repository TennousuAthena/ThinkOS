# 31 · 电视直播：iptv 插件与 tv 组件

> 2026-11-02。ADR-038，API 8（与 `nowplaying`、`tabs`、`panel` 同一版，没有另升版本）。目标：设备上看网络电视——读频道列表、同一频道合并成一个、自动测试线路并暂时停用失效的、尽量取到节目单、有专属的电视界面。
> 标记：**已实测** = 在 Lenovo ThinkSmart View（HUA0BWUT，Android 8.1，armeabi-v7a）上跑过，命令在 §8；**未验证**集中在 §9。
> 先读：`AGENTS.md` → `08-decisions.md` ADR-022、ADR-030、ADR-038 → `06-plugins.md` §4.1.3、§6.10 → `27-streaming.md` → 本文。

## 1. 结论

- **做了**：自带插件 `iptv`（`plugins/iptv`），OS 组件 `tv`（影院视图加直播界面），Lua API `tos.media.probe`。四个要求各对应一块：
  1. **解耦的列表源**：一个“源种类”是一个 Lua 模块，只回答“这段文字是不是我的格式、怎么读”；`main.lua` 不知道列表长什么样。现有 `m3u`、`json` 两种，加一种（Xtream、Stalker……）是写一个文件、在 `sources.lua` 里登记一行。
  2. **合并相同频道**：不同列表里的 “CCTV-1 综合 HD”“CCTV1”“cctv-1 [1080p]” 是一个频道、三条线路；有 `tvg-id` 时 id 相同也算同一个。
  3. **自动测试、暂时停用失效线路**：后台每隔几秒测一条（收藏和最近看的先测），失败的线路暂停一段时间，连续失败越久暂停越长，到期自动再测；第一次要播的线路播前先看一眼，死线路不再让播放器白等几秒；播放中失败立刻换下一条。
  4. **节目单**：也是可换的提供方：XMLTV（列表头里写的或设置里填的）和“每个频道一份 JSON”的地址模板。取不到就没有节目单，频道照常播，页脚说明原因。
- **专属电视控件**：`tv`（`06-plugins.md` §4.1.3）。频道横幅、节目与进度、下一档、上一台 / 下一台 / 频道列表 / 线路 / 收藏，全由 OS 画；按钮和手势只发一个事件给插件。
- **页面**：`iptv.channels`（收藏 / 最近 / 全部 / 分组四个标签，行里带正在播的节目和可用线路数）、`iptv.live`（`tv` 组件，`live` 页，由播放接管）。`channels` 在左右翻页序列里；“应用”入口与磁贴由别的工作接上（`manifest.json` 的 `apps[]`、`tile`，见 `33-apps-and-back.md`）。
- **没有 Server 也完全工作**（ADR-015）：列表和线路状态存在设备上，下次启动先显示上次的列表，再去更新。

## 2. 怎么用

设置（长按页面进入，`06-plugins.md` §11）：

| 设置 | 默认 | 说明 |
|---|---|---|
| 频道列表 1 | **预置** `https://guovin.github.io/iptv-api/result.m3u`（§10） | M3U 或 JSON 列表的地址。互联网上的必须是 https（`tos.http` 只放行私网明文，`06-plugins.md` §6.4）；局域网里可以用 http。地址前加 `json:` 强制按 JSON 读，不加则按内容判断 |
| 频道列表 2–4 | 空 | 同上，可以再加最多三个；合并时第一个列表优先 |
| 节目单地址 | **预置** `https://api.cntv.cn/epg/epginfo`（央视网自己的央视节目表，只有央视频道，§10.2） | 也可以是 XMLTV 文件（≤1 MB，不能是 .gz），或带 `{name}` `{id}` `{date}` `{ymd}` 的地址（每个频道一份 JSON）。空 = 用列表头里 `url-tvg` 写的（.gz 的不会去要） |
| 节目单时区 | 空 | 节目单的时间只有 `06:30` 这种时用，例如 `Asia/Shanghai`；空 = 本设备时区 |
| 自动检测线路 | 开 | 总开关：后台测试和播前一看都归它。给一次性地址（令牌用一次就作废）的源，关掉它 |
| 两次检测的间隔 | 10 秒（3–600） | 后台每次测一条线路 |
| 失效线路暂停 | 10 分钟（1–720） | 第一次失败的暂停时长；连续失败每次乘 3，最长一天 |
| 正常线路复检间隔 | 12 小时（1–168） | |

频道页：上面四个标签。“收藏”和“最近”是同一份列表的两个视图，“分组”列出分组、点一个分组就只看它（中间那个标签随之显示分组名，再点它取消），“全部”是全部。行：台号和频道名、正在播的节目（没有就写分组）、可用线路数（`2/3`；全不可用写 `—`；只有一条线路不写）。页脚：失败时写原因，否则写检测进度或暂停数，再否则是频道总数。点一行开始播，并回到 `live` 页；上一台 / 下一台就在这一行所在的视图里翻（收藏视图里选的台，上一台下一台只在收藏里走），跳过没有可用线路的频道。

直播页：触摸后浮出控件，十几秒后淡出（同影院视图）。竖拖仍是亮度（左半）与音量（右半）；画面左、右四分之一处双击 = 上一台 / 下一台。控件：上一台、下一台、`频道`（回频道页，离开直播页时停止播放）、`线路 n/m`（同一频道的下一条线路，只在有多条时出现）、`收藏`（实心 = 已收藏）、字幕按钮（流里有字幕轨时）。语音 / 指令：`channel up` / `channel down`。

## 3. 解耦的列表源

```
main.lua  ──下载──▶  sources.lua  ──按种类──▶  sources/m3u.lua   (#EXTM3U / #EXTINF，Kodi 的 |User-Agent=…，#EXTVLCOPT)
   │                                  └────▶  sources/json.lua  (数组或 {channels|list|items|data: […]}，一个频道可有 urls / lines)
   └─合并─▶ channels.lua
```

一个种类是返回 `{id, sniff(text), parse(text, base, opts)}` 的模块；`parse` 返回统一的 `{name, url, group?, id?, agent?, referer?}` 列表，外加列表头里的节目单地址。`sources.lua` 只做两件事：从 `json:https://…` 这样的前缀里取出种类，没有前缀就让每个种类依次 `sniff`。一个地址本身是 HLS 播放列表（有 `#EXT-X-`）时当作一个频道，名字取主机名（去掉账号密码）。限制：单个列表读 ≤900 KB 文本、≤1500 项；地址必须是合法 URI（一个坏地址会让引擎拒收整个队列，所以读的时候就丢掉）；名字清成合法 UTF-8、≤120 字节。

插件**不能读文件**（`io` 不开放，ADR-016），所以列表只能是地址：设备上的本地列表要先放到局域网里的一个 http 服务上。公网明文 http 的**列表**读不了（`tos.http` 的规则），公网明文 http 的**线路**能播也能测（走媒体的规则，`media.public_http`）。

## 4. 合并相同频道

`channels.key(name)`：转小写，去掉各种括号里的内容（`()[]<>（）【】「」［］`，用纯文本找，不用 Lua 模式，因为全角括号是多字节），去掉画质词（`hd fhd uhd sd 4k 8k 1080p … hevc backup test 高清 超高清 标清 备用 测试 …`，拉丁词按整词），再去掉空格和标点，剩下的就是 key。**CCTV 例外**：`cctv` 加数字的名字，key 就是 `cctv<数字>`（后面是别名：`CCTV-1 综合`），`+` 和 4K/8K 保留，所以 `CCTV-5` 与 `CCTV-5+` 是两个频道、`CCTV-1` 与 `CCTV-11` 也是。

`channels.merge(items)`：`tvg-id`（不分大小写）相同或 key 相同的项并成一个频道，频道的名字、分组取先出现的，缺的由后来的补；同一个地址不重复；线路按**列表顺序**（用户排的优先），同一个列表里按名字声明的画质（4K > 1080 > 高清 > 标清）、再按出现顺序排。每个频道 ≤6 条线路，一共 ≤600 个频道。台号就是合并后列表里的位置，列表一变台号会变（收藏按 key 记，不受影响）。

## 5. 线路健康：测试与暂时停用

每条线路一条记录（按地址的 FNV-1a 哈希存，约 55 字节，≤900 条）：`f` 连续失败次数、`u` 暂停到什么时候、`o` 最后一次正常、`t` 最后一次测试、`p` 最后一次真的播过、`x` 测不了、`k` = `hls`。**没有记录 = 没测过 = 当作可用**。失败一次暂停 `cooldown` 分钟，之后每多一次乘 3，最长一天；成功清零。暂停期间选台、上一台下一台、自动换线都跳过它；所有线路都在暂停时，用户点了这个频道就试暂停最快结束的那条。

**什么时候测**：

1. **后台**：每 `test_gap` 秒一条（`tos.media.probe`，§7），顺序是：暂停到期的 → 没测过的 → 测过但超过复检间隔的；同一档里收藏的频道先、最近看的次之、其余按台号。不测：屏幕 ASLEEP、正在换台（还没播上）或正在缓冲重连、没有时间校准（`tos.time.now()` 为空）、正在播的那一条、rtsp（测不了）。
2. **播前一看**：一条没测过的线路在交给播放器之前先测一次。原因（真机上量到的）：播放器对一个回 404 的 HLS 列表会再要三次，每条死线路让屏幕黑三秒多；探测立刻就知道。只在“自动检测线路”开着时做；测过的线路不再看。
3. **播放中**：引擎报 `media.error`（`network`、`http`、`format`、`decoder`……）就记失败、换下一条，画面上写“已切换到线路 2 / 3”；只有 `policy` / `permission`（网络规则不让连）不算线路的错：换下一条，全部都被拦时画面上写明原因。20 秒还没播上也算失败；播满 5 秒记成功。

**测试结果的含义**：`ok` → 正常；服务器回了错误状态（`http`）或回了网页不是流（`format`）→ 失败；`timeout` / `dns` / `tls` / `network` → 说的是网络，不是线路：**离线保护**——启动以来没有任何一次应答，或最近一次应答在 15 分钟以前，就当网络断了，5 分钟内不再测、不记失败（否则开机时没连上网会把整张表停用）；`policy` / `unsupported` → 测不了，记 `x`，一周后再看。

## 6. 节目单

提供方是返回 `{id, accepts(spec), fetch(ctx, channel), reset()}` 的模块（`guides.lua`，第一个认这个地址的用），`guide.lua` 放它们共用的东西（时间、XML 文本、查“现在播什么”）。

- **`guides/cntv.lua`**：地址是 `https://api.cntv.cn/epg/epginfo`（不带参数）。央视网自己的节目表，每个频道每天一份约 8 KB 的 JSON（`{"cctv1": {"program": [{"t": 标题, "st": 开始秒, "et": 结束秒}]}}`）。服务要它自己的频道 id，列表里没有，所以由提供方按频道名的规范形式（`channels.key`）对：`cctv1`…`cctv8`、`cctv10`…`cctv13`、`cctv15`…`cctv17` 照写，`CCTV-5+` → `cctv5plus`，`CCTV-9` → `cctvjilu`，`CCTV-14` → `cctvchild`，`cctv4k`、`cctv8k` 照写；不是这些的频道不发任何请求、也不算失败。服务的“一天”是北京日（固定 +8，不看设备时区）；当天最后一档在两小时内结束就再取明天的一份（一天到 23:59 为止）。

- **`guides/template.lua`**：地址里有 `{`：每个频道请求一份 JSON。`{name}`、`{id}`（百分号编码）、`{date}`（2026-11-02）、`{ymd}`。认三种常见形状：`{epg_data: […]}`、`{programs|programmes|data|list: […]}`、直接是数组；时间可以是 `06:30`（按节目单时区取当天，跨午夜自动进位）、epoch 秒或毫秒、ISO 8601。
- **`guides/xmltv.lua`**：整份 XMLTV 一次读完，保存 6 小时：读 `<channel>`（`id` 与 `display-name`）对上我们的频道（先按 `tvg-id`，再按名字的 key），读 `<programme>`（`start`、`stop`、`title`），只留 −30 分钟…+12 小时、每个频道最多 24 档。频道段与节目段分开扫（先用纯文本找第一个 `<programme`）：在真机上，对整份文档做一次“找最后一个 `</channel>`”的模式匹配就会用光 50 ms。每 40 档让一次 CPU。

**取不到的几种**（页脚写原因，频道照播）：超过 1 MB（`tos.http` 的上限）、是 .gz（`tos.http` 不解压）、HTTP 失败、没有可读的节目。没有定义的字段都当“没有”，不猜。取过的频道 10 分钟内不再取；6 小时内且手上的节目已覆盖到两小时以后的也不再取。

## 7. `tv` 组件与 `tos.media.probe`

`tv` 是 `Video`（影院视图）的一个模式，不是另一个播放器（ADR-022）：同一块 TextureView、字幕、缓冲与错误卡片、亮度与音量手势；不同的是浮出的东西——`TvOverlay`（`ui/TvOverlay.kt`）取代标题与进度条，一排按钮换成上一台 / 下一台 / 三个药丸，没有快进快退和进度条。频道对象由 `TvChannel.parse`（`ui/TvModel.kt`，不依赖 Android，有 JVM 测试）读，类型不对的字段当没有。节目进度由 OS 每秒按 `WallClock` 画。按钮事件经 `MediaComponents.create` 的 `emit` 进 `PluginRuntime.event`，和别的 `tap` 一样（`tapped[plugin]` 也记，所以按钮按下后的 `tos.page.focus` 算“回应点击”）。没有 `media` 权限时 `tv` 不画（安装器和打包器都拒绝）。

`tos.media.probe(url, {headers})`（`media/MediaProbe.kt`，`MediaCapability`）：见 `06-plugins.md` §6.10。它存在的原因：`tos.http` 拒绝公网明文，而电视源多是公网明文 http，用它测就一条都测不了；它走播放的网络规则，所以能测播放能播的所有地址。读开头 16 KiB（带 `Range`，服务器不理会也只读这么多）、HLS 顺着第一个子列表和第一个分片再问两次（死频道常常还能给出列表）、200 的网页判为 `html`、全程 ≤12 秒、同时 ≤2 个。**一次测试不动当前的播放会话**。

### 8.1 设备测试 `iptv_device.py`

Mac 上起一个测试台（两份频道列表、一份节目单、三路 ffmpeg 做的 HLS，另有“404”和“200 但是网页”的线路），设备经 `adb reverse` 访问，不需要局域网。脚本像人一样：通过调试命令设置插件的设置，打开频道页、点频道、按电视界面的按钮、双击画面；再读插件的存储（`run-as` 读 `files/store/iptv.json`）和测试台的请求日志核对设备到底要了什么。结束时重置插件设置、停止播放、放开所有 hold。调试包的 `setting` 命令为此多了 `scope`（插件 id）和 `reset`。

**35 / 35 项通过**（2026-11-02，最终包；`artifacts/iptv/` 有截图）：

- **列表与合并**：两份列表合成 5 个频道，线路数 3 / 2 / 1 / 3 / 3，第一份列表的线路在前、同一份里画质高的在前；列表头里的节目单地址被记下；频道页列出全部频道、标签与页脚（`共 5 个频道`）。
- **失效线路与换线**：频道 1 的前两条线路一条回 404、一条回 200 的网页，第三条是活的：设备按顺序试了三条，第三条播上；记录里前两条 `f = 1` 并暂停 10 分钟，活的有 `o` 和 `p`。上一台 / 下一台、画面左右边缘双击都换台；回到频道 1 时**直接要活的那条**，暂停的两条没有再被问；线路药丸选到频道 2 的下一条（死的），自动回到第一条，画面写“已切换到线路 1 / 2”。
- **电视界面**：横幅（台号、频道名、分组）、正在播的节目与时间、下一档、上一台 / 下一台、`频道` `线路 3/3` `收藏` 三个药丸、字幕按钮；收藏药丸改了存储里的收藏并在“收藏”标签里出现；`频道` 药丸回频道页并停止播放。截图 `live-overlay.png`。
- **后台测试**：测试间隔 3 秒时，频道 4 没人播过的三条线路被逐条测完：死的与“200 的网页”暂停，活的不暂停并记为 HLS；测试请求带 `Range: bytes=0-16383` 和 `User-Agent: ThinkOS/1`；最后 12 条线路全测过，频道页显示 `1/3`、`1/2`，页脚 `12 条线路中有 7 条因失效而暂停`（`channels-tested.png`）。
- **播前一看**：频道 5 的第一条线路是死的、从没测过：它的地址**只被问了一次**，是测试问的（带 `Range`），播放器没有见过它；点下去到开始播 **1.4 秒**。对比：关着检测时点频道 1（前面有两条死线路），播放器对死的那份列表问了 4 次、前后 3.1 秒，第三条线路在第一次尝试后 3.2 秒才被要到，点下去到开始播 4.4 秒。两个频道的死线路数不同（2 和 1），这不是严格的对照，但“死 HLS 列表让播放器白等约三秒”是播放器自己的行为，直接量到的。
- **没有崩溃**；结束时插件的设置被重置、会话停止、所有 hold 放开，收藏和频道页的标签放回原样。

测试中发现并修好的两件事：（1）一个频道离开列表后它的线路记录在内存里被清了，但**没有保存**，下次启动又读回来——现在清理会安排保存（Lua 单元测试覆盖）；（2）播放器对死线路的三次重试就是上面的 3 秒，所以加了播前一看。

## 9. 已知限制与没做的

- **XMLTV 超过 1 MB 或是 .gz 读不了**：`tos.http` 的 1 MiB 上限且不解压。全国的完整节目单通常是几十 MB 的 .gz，要用这种源需要一个转成小 XMLTV 或每频道 JSON 的中间服务（或以后给 `tos.http` 加流式读取）。
- **没有重试的播放器等待**：一条没测过、也没开自动检测的死 HLS 线路，播放器会再问三次，约三秒才换下一条。
- **测一圈要很久**：默认 10 秒一条，600 个频道、每个两三条线路要几个小时；所以收藏和最近的先测，真要播的线路播前一看。
- **一次性地址（令牌用一次就作废）的源**：测试和播前一看都会用掉一次，关掉“自动检测线路”。
- **rtsp 线路不测**：播放照常。
- 没做：回看、录制、台标（`tvg-logo` 读了不用）、设备读本地文件做列表、频道改名与手动排序、内置频道表、“应用”入口、`radio`。
- **台号**是合并后列表里的位置，列表更新后会变。
- 频道页是 `focus` 版式里的一个列表，一屏放不下时上下滑动；一个视图最多 500 行（插件状态上限 256 KiB）。

### 没有验证的

- **真实的公网频道列表和节目单从没用过**：仓库里没有任何公网列表，所有验证都用本地测试台；真实列表里的怪格式只靠解析器的单元测试覆盖。
- **长时间运行**：后台测试跑一整夜、几百个频道时的 CPU 与内存没有测（性能测试按约定先告知再跑）。armv7 上量过的只有：Lua 单次切片最长约 23 ms、600 个频道的列表峰值 2.5 MB。
- **界面语言与方向**：设备上只试了中文界面和横屏。其余十种语言的文案只检查了键一致、占位符一致；竖屏、阿拉伯语 / 乌尔都语（从右到左）下电视界面的排布没有看过。
- **节目单时区**：设备上只试了 UTC 的 XMLTV 和带时区的时间；`06:30` 这种时间配 `epg_zone` 只在 Lua 里验证过，没有在设备上对真实服务试。
- **rtsp 频道**：没有在设备上试过（播放走原有路径，测试不碰它）。

## 10. 预置的列表与节目单（2026-11-02）

用户要求预置 `https://guovin.github.io/iptv-api/result.m3u`（Guovin/iptv-api 项目每天生成的公开频道列表），并要求再看看能不能找到它的节目单。做法：`manifest.json` 里 `source_1` 的默认值就是它，别的列表默认空；APK 里没有列表的副本（设备第一次联网时自己去读，之后每 6 小时和改设置时再读；读不到就按 30 秒、1、2、5、10 分钟、之后每半小时一次地重试；没有网络时先显示上次存下的）。清空或改掉这个设置就不再用它。

**来源与许可**：iptv-api 项目的代码是 AGPL-3.0；列表是它生成的数据（别人的流地址的汇总），项目的免责声明要求使用者自行确保所播内容的授权，并特别提到中国大陆。所以这里只预置**一个可改的地址**，不把列表拷进 APK、也不拷进仓库（本项目的源码是 MIT，完整版 APK 是 GPLv3，ADR-043）；用户要不要保留这个默认由用户定。

**一个现实问题**：这台设备所在的网络连 `guovin.github.io`（GitHub Pages，`185.199.108.153`）时好时坏：23:43 和 23:55 连得上，00:05、00:11、00:13 的连接在 `tos.http` 的 3 秒限制内连不上。只靠一个地址的预置，在这样的网络上第一次启动可能要等好一阵才有频道，所以读不到时会一直重试（见 10.1 第 6 条）。想要“一开机就有频道”需要把列表的一份快照放进插件，那是上面许可与授权的问题，没有做，见 10.3。

### 10.1 这份列表是什么样的（2026-11-02 实测）

- 208 KB，839 个条目，读取后 801 项（去重、丢掉 2 条 rtmp），合成 **321 个频道、768 条线路**（每个频道最多留 6 条），分在 35 个分组里；每条都有 `tvg-id`、`tvg-name`、`tvg-logo`。读取与合并在 armv7 沙箱里最长一片 10.6 ms、峰值 1.9 MB，存下来约 90 KB（256 KiB 的存储上限内）。
- 全列表 559 条是公网明文 http（其中 90 条是 IPv6 地址）、278 条 https。留下来的 768 条里 **518 条是 http；321 个频道里 143 个一条 https 线路都没有**。`media.public_http`（系统设置“允许互联网明文 HTTP”，默认关，ADR-022）关着时，这些频道会被拦下，画面上写明原因和怎么开；开着才都能试。**这个默认没有改**，要不要打开由用户定。（这台测试设备上该开关是开着的。）
- 真机上用这份列表试出来、已修的问题：
  1. 第一项是一个叫 `2026-10-12 11:25:50` 的假频道（列表的更新时间，带着 CCTV-1 的 `tvg-id`）：合并会按 id 把真正的 CCTV-1 并进它，频道 1 就叫成日期。现在名字是日期的条目不算频道（`channels.isChannel`）。
  2. 满是死地址（IP 不通、超时）的列表：旧的离线保护要“先有过一次应答”，第一批测试全超时就当成网络断了，永远测不出失效线路；播前先看一眼也把超时留给播放器去等（最长 20 秒黑屏）。现在不应答时先问一次第一个列表自己的地址：通就是线路的错（`networkUp`、`judge`）。
  3. 分组名带 emoji（`📺央视频道`）：设备字体不认 `🪁`（Unicode 12），画成一个空框；装饰 emoji 也和扁平单色的界面不搭。现在分组名只留文字（`channels.label`）。
  4. 列表头里的节目单 `…/epg.gz` 是 404（见下）：去要它只会让页脚永远写“无法加载节目单”。现在头里写的 .gz 不去要；用户自己填的地址照常去要并说明原因。
  5. 一条线路被网络规则拦下（明文 http 而开关关着）只说明“测不了”，之前要一周后才再看，用户打开开关后要等一周；现在一小时后再看，播放前也再看一眼。
  6. 列表第一次没读到（设备上亲眼见到：同一台设备，23:43 读到了，00:05 连 `guovin.github.io` 在 3 秒内没连上）：之前要等 6 小时的下一次定时读取，预置列表的设备就会好几个小时没有频道。现在读不到就重试（30 秒、1、2、5、10 分钟，之后每半小时），读到为止；只读到几个列表中的一部分时也一样补读。
- 设备上的结果（最终包，用户没有设置任何东西）：读到 321 个频道、768 条线路；点 CCTV-1 播上了（HLS，1920×1080 H.264 + AAC，直播，没有重试和错误）；后台测试自己在跑，页脚是“正在检测线路：已查 n / 768，暂停 m”，头 22 条线路里 15 条正常、7 条失效被暂停。截图在 `artifacts/iptv/preload-*.png`。

### 10.3 没做、等用户定的几件事

1. **要不要打开 `media.public_http`**（上面 10.1）：不打开，这份列表近一半的频道播不了；打开，明文传输（ADR-022）。这个默认没有改。
2. **要不要把列表的快照放进插件**，让第一次启动不依赖网络：好处是一开机就有频道；代价是快照会过期（这份是 2026-10-12 的，三周了）、占 APK 约 90 KB、以及上面的许可与授权问题。我的建议是不放，用重试和“读过一次就离线可用”解决；如果设备的网络一直连不上 GitHub，更合适的办法是让用户自己的 Server 缓存这份列表再下发（ADR-015：Server 只负责下发与管理）。
3. **卫视的节目单**：要不要接（10.2 末尾）：约 35 个卫视名对 id，约 33 个频道受益，地方台仍然没有。


### 设置输入格式（UI-03）

频道列表支持 M3U 或 JSON 地址，强制 JSON 可在地址前加 `json:`。节目单可用 XMLTV 或每频道 JSON，JSON 地址模板支持 `{name}`、`{id}`、`{date}`。整份节目单上限 1 MiB，不接收 gzip 包；默认提供方是 `guides/cntv.lua` 的央视网节目表，地址由 manifest 的 `epg_url` 默认值给出，仅适用于央视频道。这些格式说明留在文档，输入框只显示短占位符。
