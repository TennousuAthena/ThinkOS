# 08 · 已定决策（ADR）

> 这里的结论**已经拍板**，开发时不要重新讨论；有异议请记录到本文件末尾的「待复议」区。

## ADR-001 用 View 体系，不用 Jetpack Compose

- **背景**：Compose 在 A53 + 2GB 上内存与启动开销偏高
- **决策**：使用传统 View + 自定义 View + Lottie
- **代价**：失去声明式 UI，需要手写状态绑定
- **依据**：设备性能基线（见 `docs/02-device.md`）

## ADR-002 不用 WebView 承载主界面

- **决策**：主界面必须是原生渲染
- **原因**：WebView 100 版在 A53 上实测卡顿；产品定位要求高帧率动画
- **例外**：不排除少量辅助页面（如设置里的外链）使用系统浏览器打开

## ADR-003 语音功能降级为可选模块

- **决策**：主链路不含语音；只保留唤醒词 + 5 个固定指令，且默认关闭
- **原因**：单麦远场拾音差；完整语音链路会与 UI 抢内存和 CPU
- **影响**：产品定位从「AI 伴侣」改为「桌面智能终端」

## ADR-004 摄像头采用三档策略（L0/L1/L2）

- **决策**：常驻 1fps 存在检测；仅在检测到人且近期有交互时开启 10fps 手势；拍照手动触发
- **原因**：持续手势推理会让 CPU 长期占用 40%+
- **收益**：平时占用降到 ~5%

## ADR-005 业务逻辑全部放在 Server 端 —— ⛔ 已被 ADR-015 取代

> 设备现在是自主运行的 OS，插件逻辑在设备上执行；Server 只负责下发、管理和可选的重活。以下保留原文作记录。


- **决策**：设备端只做渲染、采集、播放；不解析业务规则
- **原因**：设备算力弱；Server 端升级迭代不需要重装 APK
- **影响**：设备强依赖局域网，需要离线兜底（见 ADR-009）

## ADR-006 不依赖 Home Assistant

- **决策**：自建轻量服务，不引入 HA
- **原因**：HA 会带来沉重的运行时与概念模型；项目目标是独立的伴侣终端
- **例外**：可以**参考** kiosk-satellite / View Assist 的交互与实现，但不在运行时依赖它们

## ADR-007 自研 Kiosk Launcher，不用第三方底座

- **背景**：评估过 Fully Kiosk（闭源但成熟）、kiosk-satellite（需 HA）、DisplayLauncher（过小）、WallPanel（停更）
- **决策**：自研
- **原因**：需求（自定义动画 + 卡片系统 + 后续插件）任何现成壳都覆盖不了，最终都要拆掉
- **兜底**：开发期可临时安装 Fully Kiosk 保证设备可用

## ADR-008 插件在 Server 端运行，设备端只渲染 —— ⛔ 运行位置已被 ADR-015/016 取代

> 插件改为在设备上运行（声明式视图 + Lua）。**仍然有效的部分**：设备端只支持固定的渲染词汇，插件不能自造类型。


- **决策**：插件是 Server 端的进程/协程，通过卡片 JSON 下发 UI
- **原因**：设备无性能余量；插件沙箱更简单；任何语言都能写
- **限制**：设备端只支持固定的渲染词汇，插件不能自造类型（词汇范围已由 ADR-013 扩展为：页面版式 + 卡片模板 + 组件）

## ADR-009 必须支持离线兜底 —— ✅ 由 ADR-015 强化

> 离线不再是“兜底”，而是正常运行状态之一：插件在设备本地运行，Server 不在时功能完整（仅失去下发、通知中转与语音）。


- **决策**：与 Server 失联时，设备仍可用：时钟、本地相册（缓存）、本地音乐
- **原因**：Server 睡眠/重启时设备不能变砖头
- **实现**：最后一张卡片缓存到本地；离线状态显示右上角小圆点

## ADR-010 targetSdk 固定 27

- **决策**：`minSdk=27`、`targetSdk=27`
- **原因**：与设备一致，避免新行为差异（后台限制、存储、通知渠道）
- **代价**：无法使用需要更高 targetSdk 的库或 API

## ADR-011 客户端用 Kotlin 原生，不用 Flutter

- **背景**：考虑过 Flutter（开发效率、跨平台）
- **决策**：Kotlin + View 体系
- **理由**：本项目只有一台设备、一个平台，跨平台收益为零；而 2GB 内存、冷启动 <3s、Kiosk 系统 API、相机/音频链路都需要原生直连
- **代价**：界面代码不能跨平台复用

## ADR-012 服务端用 Go，插件走子进程 JSON-RPC —— ⚠️ 已由 ADR-015/016 修订

> Server 仍用 Go。子进程 JSON-RPC 只保留给**可选的 Server 端服务插件**（只提供数据，不提供界面）；功能插件改为设备上的 Lua 插件。


- **背景**：服务端在 Go / Rust / Python 之间选择
- **决策**：宿主用 **Go**；插件是**独立进程**，通过 stdin/stdout 交换 JSON-RPC 2.0
- **理由**：
  - 负载是 IO 密集（WS/HTTP/JSON），Go/Rust 都够；Go 的并发模型和开发速度更合适
  - 本机已装 go1.27.3，无需新工具链
  - 插件用子进程后**语言自由**（Python/JS/Go 都行），且崩溃不影响宿主
- **代价**：多一层进程通信；插件不能共享宿主内存
- **若将来需要重 CPU 处理**（如音频分析），用 Rust 写独立 sidecar，不重写宿主

## ADR-013 插件优先：页面即插件

- **背景**：产品需要像小爱一样靠插件加功能，且插件由别人编写、加功能不重装
- **决策**：ThinkOS 自身不实现任何具体功能。时钟、天气、相册、音乐、通知、首页**全部是插件**；每个整屏页面都是某个插件声明的 page，设备上左右翻页就是在插件之间切换。APK 只是运行时，提供 Lua 插件运行时、页面路由、舞台、动效、页面版式、卡片模板、播放器、感知（插件运行位置见 ADR-015/016）
- **原因**：功能迭代全部发生在插件里，不重装 APK；自带插件与第三方插件同一套接口，没有私有通道
- **约束**：插件只描述内容与语义，长相与动画由设备决定；渲染词汇只随 APK 升级扩展
- **来源**：用户决定（2026-10-29）。详见 `03-architecture.md` §2.1、`06-plugins.md`

## ADR-014 整机体验参照 iPhone「待机显示」（StandBy）

- **决策**：交互与观感以 StandBy 为蓝本：小组件 / 照片 / 时钟三个默认视图左右滑切换，上下滑切换样式；小组件为双栈智能叠放并按相关度轮换；实时活动全屏接管；通知以大图标出现；暗光下整屏变红的夜间模式；横屏为主形态；**白天浅色、夜里深色**，由环境光自动切换（手动锁定等设置见 ADR-017）
- **落地**：全部建立在 ADR-013 插件优先之上——三个视图分别是 `home`、`gallery`、`clock` 插件的页面；样式切换是页面的变体；夜间模式由设备在合成阶段统一处理，插件无感
- **来源**：用户决定（2026-10-29）。详见 `03-architecture.md` §2.2

## ADR-015 设备自主运行，Server 是下发与管理装置

- **背景**：旧模型里 Server 驱动设备的每一帧内容，设备离不开 Server
- **决策**：设备端 ThinkOS 是一个有自主性的 OS：插件、页面路由、状态、配置、照片集都在设备本地，**没有 Server 也能完整使用**。Server 的职责是：设备登记与配对、下发（插件包、配置、照片集、APK 更新）、中转（手机通知、远程指令）、可选增强（语音识别、Server 上的音乐库、Server 端服务）、观测（指标、日志、崩溃）
- **通讯**：从“Server 推画面”改为“期望状态同步”——设备通过 HTTP 拉取期望状态并在本地对齐、回报实际状态；WebSocket 只是可选的实时通道（nudge、通知、远程指令、服务调用、语音）
- **影响**：取代 ADR-005；ADR-008 的运行位置作废；ADR-009 强化；ADR-012 修订；协议见 `05-protocol.md`
- **来源**：用户决定（2026-10-29）。详见 `03-architecture.md` §1、§3.9、§4

## ADR-016 设备插件 = 声明式视图 + Lua 脚本

- **决策**：插件包由 manifest、声明式视图（JSON，用 `{{path}}` 绑定状态）、可选的 Lua 脚本和资源组成；没有逻辑的插件可以不写 Lua。脚本只能通过 `tos.*` API 访问能力，按 manifest 权限授予
- **原因**：声明式部分保证外观统一、横竖屏与动画由设备负责；Lua 轻量、启动快、内存小，适合 A53 + 2GB；在沙箱内运行，加功能不重装 APK
- **实现方向**：官方 Lua 5.4 源码随 APK 用 NDK 编译（只有 armeabi-v7a），自写 JNI 桥；所有 Lua 在单独的插件线程运行，带 CPU/内存预算（细节为提议，见 `03-architecture.md` §3.7、§9）
- **来源**：用户决定（2026-10-29）。详见 `06-plugins.md`
- **分发形态**：插件不再打成 `.tpk`（zip），改由 Git 仓库分发，见 ADR-018

## ADR-017 设置：系统级 + 页面级；外观不开放接口

- **背景**：希望 OS 能像 Apple Watch 那样被定制。评估过一套“部件样式系统”——表盘 = 固定部件类型 + 可换样式 + 槽位数据类型，再加样式包 / 表盘包生态——结论是**过于复杂**，且与目标相悖：在 AI 时代，想要什么样的页面，让 AI 写一个页面插件即可，不需要 OS 预留样式扩展点
- **决策**：
  1. **外观不开放接口**（ADR-025 修订：仅 `tile` 底色可由插件定义）。页面就是普通插件，长什么样由插件作者（或 AI）决定；OS 不引入样式语言、表盘包、部件皮肤等扩展点。ADR-013 的“渲染词汇只随 APK 升级扩展”保持不变
  2. OS 只提供**设置**，分两级：**系统级**（OS 自己声明，一份 schema）和**页面级**（每个插件在 manifest 的 `settings` 里声明）。两级共用同一种声明格式，类型只有 `bool` / `choice` / `number` / `text`
  3. 设置值由 OS 的设置存储保管：按 schema 校验、原子写盘，按“APK 默认值 ← Server 下发 ← 设备上修改”叠加，设备上的修改回报给 Server。插件只读（`tos.config`、`config` 事件），不能自己写
  4. **设置界面本身是插件**：内置 `settings` 插件按 schema 自动生成表单，与其他插件走同一套 `tos.*`，只多一个系统权限 `system.settings`（现阶段只授予 APK 内置插件）。OS 补充 `form` 页面版式，提供原生控件
  5. 入口：**长按任意页面**打开该页面所属插件的设置，设置页里可进入系统设置。**原生救援菜单**（隐藏的双指长按 5 秒）是唯一保留的原生设置界面，`settings` 插件不可用时自动回退
- **否决**：部件样式 / 表盘 / 样式包系统；复杂功能（complication）槽位与数据类型体系；长按编辑模式（长按改为进入设置）
- **影响**：manifest 的 `config` 字段升级并更名为 `settings`；`04-ui-spec.md` §9 由“以后要开放的设置”变为系统级设置清单；`09-roadmap.md` 新增 M0.5
- **来源**：用户决定（2026-10-30）。详见 `06-plugins.md` §11、`04-ui-spec.md` §9–10、`03-architecture.md` §3.18

## ADR-018 插件以 Git 仓库分发（取代 .tpk）

- **背景**：单个 zip 文件安装太麻烦；插件由第三方编写，最自然的载体是 Git 仓库
- **决策**：
  1. 一个插件 = 一个 Git 仓库里的一个目录（默认仓库根目录，也可用子目录）。**不再有 zip / `.tpk`**
  2. **Git 只在 Server 上用，设备不碰 Git**。Server 调用本机 `git` 取回仓库，校验后把插件的文件按 sha256 入库，通过期望状态逐文件下发；设备装好后照常离线运行
  3. **版本 = git tag**（SemVer，`v1.2.0` 或 `1.2.0`），安装时解析并锁定为 commit SHA（tag 可被改动，commit 不会）
  4. **发现 = 仓库 topic `thinkos-plugin`**（GitHub 的 Topics，不是 git tag）：GitHub、GitLab、Gitea / Forgejo（含 Codeberg）都支持按 topic 搜索。其它平台或私有仓库直接粘贴 URL 手动导入。搜索结果只是线索，能不能装以取回后的校验为准
  5. 安装前显示权限并由用户确认，更新新增权限需再次确认。**跟踪分支**（`main` 等）只开放给手动导入的插件，从搜索结果安装的一律按 tag
- **安全**：Server 只取回和校验，不执行仓库中的任何内容（无 hook、无脚本、无构建步骤）；不检出工作区，直接读 git 对象；拒绝符号链接、子模块、超限文件；传输协议限定 `https` / `http` / `ssh`；插件仍只能在设备 Lua 沙箱内、凭已确认的权限运行
- **影响**：ADR-016 中的“包”变成“文件集”；设备端安装器、APK 内置插件、`tools/plugin-push.sh` 全部改为目录形态（M0.5）；Server 的 `bundles` 模块改为 `registry`（M2）；V1 的“插件包签名”改为可选的 git 签名 tag 校验
- **来源**：用户决定（2026-10-30）。详见 `06-plugins.md` §12、`05-protocol.md` §3、`03-architecture.md` §3.7.5

## ADR-019 随 APK 携带 IANA 时区规则

- **背景**：设备 ROM 的 tzdata 固定为 2021a，无法正确处理其后各地调整的时区与夏令时。
- **决策**：APK 携带 `shared/tzdata/` 的 IANA 数据；`ZoneClock` 解析 TZif 与 POSIX 规则，所有插件时间格式与当地日边界都经此入口。系统时区 ID 仍由 Android 设置决定，不修改 ROM。
- **验证**：`tools/gen_tz_golden.py` 用 CPython `zoneinfo` 独立生成黄金向量，覆盖全部打包地区；未知 ID 只在普通时钟格式化时回退系统时区，天文地点的显式非法时区直接报错。
- **来源**：交接文档中已实现的设备约束与用户“日期时间跟随系统”要求（2026-10-30）。

## ADR-020 语言与日期时间遵从系统

- **决策**：系统字符串与内置插件提供 11 张语言表（含简繁中文）；按语言、脚本、地区逐级回退至英文。命名格式 `@time`、`@dateFull` 等由 OS 根据系统 locale 与 12/24 小时设置解析；插件不内嵌固定日期格式。格式化始终使用 ADR-019 时区规则。
- **边界**：系统设置、插件文案与无障碍文案走统一字符串源；外部 API 的原始地点名保留服务返回的本地化文本。
- **来源**：用户多语言与系统时间格式要求；补记交接时已有实现（2026-10-30）。

## ADR-021 本地位置与天文能力

- **决策**：位置保存在系统设置 schema。自动模式仅取设备时区的代表城市坐标，明确标记来源为时区推定；手动模式可选城市/区县或直接输入坐标与海拔。设备没有 GPS。在线搜索是可选辅助，失败不影响手填和天文计算。
- **能力**：`location` 权限允许 `tos.location.get()`、`tos.astro.sun(ms[, place])`、`tos.astro.moon(ms[, place])`；不依赖位置的 `tos.astro.seasons(year)` 无需该权限。日月计算在独立任务线程运行并挂起 Lua，结果回到插件线程；沿用挂起任务的预算、取消和所有权检查。结果为数据，可绑定 OS 组件，组件不向插件反向开放坐标。
- **时间与模型**：民用日期由自带时区库计算，涵盖 DST 的 23/25 小时及午夜空档。太阳事件按当天太阳中天前后各 12 小时的太阳窗口计算，月亮升落按当地日计算。几何高度与固定 34′ 地平折射分开；太阳上缘、海拔地平俯角、月球站心视差分别处理。月相时刻和月龄按真实黄经差求根，不使用平均朔望月。
- **验证**：计算模型与独立 PyEphem/libastro 黄金向量对照；不将测试库或 Python 带到设备。当前固定 ΔT=69.2 秒，面向 2020 年代；对外太阳/月球日期限定 2020–2050，季节计算限定 1950–2050。未授时设备返回空天文数据，界面显示占位。
- **来源**：用户要求日照/天文、城市（区县）位置及交接 §4-A/B；本地离线能力按 ADR-015 落地（2026-10-30）。

## ADR-022 设备持有媒体会话与播放队列

> 当前状态：媒体核心与独立测试已有，Runtime/Lua/权限接线尚未启用。用户最新指示本轮仅测试 UI，完整功能暂缓；以下为后续实现方向。

- **决策**：设备端采用 Media3 ExoPlayer 1.9.2，复用现有无原生库依赖；音视频共用一个 OS 媒体会话和队列。播放器操作在主线程，插件通过 `tos.media.*` 请求，队列索引对 Lua 从1开始，空队列为0。所有者被替换、移除或播放错误时收到事件。
- **状态**：OS 发布保留键 `media`，允许有媒体权限的页面直接绑定曲名、封面、进度及播放控制；插件只负责来源和数据，不逐帧更新播放器 UI。视频由原生 TextureView 承载。
- **网络与离线**：本地文件可离线播放；外部目录走 Android 运行时读取权限。网络媒体用 OkHttp 数据源，明文只允许私网地址，校验 DNS 与实际连接地址，拒绝 HTTPS 降级，沿用普通插件 HTTP 的同一规则。任何 Server 都是可选来源。
- **配置**：音量、循环、随机和来源等产品选项由插件或系统设置 schema 管理。播放器不引入另一份 SharedPreferences。
- **验证**：APK 检查只允许 armv7；队列与网络策略有单元测试；播放连续性、频谱 CPU/帧率和视频表现以真机记录为准，未实测不算完成。
- **来源**：用户要求 OS 提供音视频能力、插件解耦数据与显示；交接 §4-D（2026-10-30）。

## ADR-024 OS 图片接口与 Bing / 本地相册

- **决策**：API 3 开放 `image/carousel` 与 `tos.library.list`。Lua 只提供照片清单/文字与设置，OS 统一执行授权、边界检查、采样解码、EXIF、原生连续缓动平移、属性转场和生命周期；自带 gallery 不使用私有通道。
- **交互与流畅性**：用户进一步要求上下浏览历史和连续动画；carousel 统一提供上下拖动，手动首尾不循环，横向翻页和长按仍归 OS。平移改为原生属性动画，不再使用待机 5fps；方向随机，12 秒最短单程与 45dp/s 默认速度上限都经设置 schema。照片 float 时间采用白字与窄黑边。
- **完整画面**：按用户要求不永久裁图。`pan` 扫过整个溢出轴并按速度上限延长停留；`contain`、关闭平移或减少动画时整张缩放。无 Ken Burns 裁边；支持轮播、固定转场和字幕。
- **来源与边界**：用户补充要求微软每日一图后，gallery 默认设备直连 Bing，可选应用私有外部目录或合并来源；元数据只走公开 tos.*，网络图片下载和磁盘缓存归 OS 通用能力。Server 下发/管理、自定义 JSON 源继续暂缓。`controls/video/tos.media` 不随 API 3 自动解除暂缓。不增加 READ_EXTERNAL_STORAGE，不接权限弹窗或修改 Device Owner。
- **缓存与署名**：缓存先读，OS URL 缓存最多 50MiB/512 项，单 URL 合并下载、临时文件原子提交、显示中的文件不淘汰。Bing 清单独立持久化；title 与 credit 分开，署名不随字幕隐藏。公网 HTTPS/私网 HTTP 和重定向策略复用 MediaHttpClient。
- **安全和资源**：本地文件最终打开仍经 LibraryAccess 授权；单文件≤8MiB、≤32MP、长边≤8192，交付位图≤窗口像素×1.5 且≤2MP/长边4096。单 Decode 线程，当前+转场两张；离页/ASLEEP/Activity 停止取消任务并释放引用，旧插件代际不得回写。
- **来源**：用户“开发相册，暂不实现与上游服务通信”“图片不要裁，做平移和轮播，优先展现 ThinkOS 接口”，后明确“我的微软每日一图怎么没实现出来”（2026-10-30）。ADR-023 仍保留给未批准的 HTTP 通知提案。

## 待复议

## ADR-025 磁贴网格与插件自定义底色（2026-10-31）

- **状态**：接受；用户决定磁贴先于播放器，使用 API 4。播放器计划顺延 API 5 / ADR-026。
- **决策**：新增 OS 固定版式 `tiles`、模板 `tile`。修订 ADR-017 第 1 条，仅磁贴底色开放 `color`，接受 `#RRGGBB` 或绑定；页面引用 > 卡片 > 系统 accent，非法运行时值逐级回退并记 warn。
- **边界**：文字、图标、内容前景由 OS 按底色自动选黑/白，最低对比度约 4.58:1。字号、圆角、像素、排布和动画仍归 OS；其它版式与组件不开放颜色。没有样式语言、主题文件、皮肤包或继承规则。夜间滤镜仍由根层合成。
- **行为**：首次适配网格不滚动，放不下的磁贴丢弃；点击 opens、长按所属插件设置；离页/AMBIENT 停止翻面，离线保留本地状态。实现与验收见 `23-tiles-plan.md`、`24-tiles-validation.md`。
