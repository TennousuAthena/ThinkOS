# 45 · 模式：白天、红移、睡眠

> 2026-11-04。所有者要把设备的几种状态规划清楚：**白天**；**红移**（原来叫“夜间模式”，今后统一叫这个名字）；**睡眠**（免打扰：音量完全静音，屏幕完全不显示）。要规划怎么设计、怎么切换，包括用户设置、当地日出日落、光线传感器和用户的触摸使用。ADR-048，任务是 `36` 号文档的 MODE-*。
> 2026-11-05状态：模式决策、设置与控制面板、睡眠静音及媒体/投屏拒绝已实现，0.1.15真机验收进行中，尚不宣称本轮通过。背光0、偷看与整晚验证仍待MODE0人工步骤；下文的全黑与偷看效果是目标，不是当前已验能力。默认值按DEC-9/10执行，所有者可推翻。

## 0. 一页纸

- **三种模式，一个状态机：**`ModeController`（`core/`）。输入：手动切换、睡眠时间表、日落日出、环境光、触摸。输出：`DAY`、`REDSHIFT`、`SLEEP`。
- **优先级：**手动 > 睡眠时间表 > 红移（日落日出加环境光）> 白天。
- **红移：**沿用现在的“夜间模式”（整屏红色单色，最低亮度），只改名字，并加上日落日出的触发方式。
- **睡眠：**背光关到 0、所有声音静音或拒绝、新的投屏、通话、蓝牙连接一律不接；触摸**双击**可以“偷看”10 秒；到点自动结束，先回到红移或白天，不会一下子全亮。
- **白天：**沿用现有的浅色和深色主题（按环境光、日出日落或固定）。
- **内部名字：**`Theme.NIGHT` 保留；`theme.night` 只作隐藏兼容入口，旧值按层迁移并消费（§5）。用户看到的词只有“白天、红移、睡眠”。

## 1. 命名

| 用户可见 | 内部 | 说明 |
|---|---|---|
| 白天 | `Mode.DAY`；主题 `LIGHT` / `DARK` | “浅色”“深色”仍是白天里的两种主题 |
| **红移** | `Mode.REDSHIFT` ＝ `Theme.NIGHT` | 设置入口为 `redshift.trigger`；11语名称统一，旧 `theme.night` 隐藏兼容 |
| 睡眠 | `Mode.SLEEP` | 新增；和注意力状态 `ASLEEP` 不是一回事（§2） |

**撞词已处理：**`attention.to_asleep_s` 的用户标签为“无人变暗”（DEC-9），内部 `ASLEEP` 不变，与睡眠模式分开。

## 2. 实施前基线（2026-11-04）

本节保留原有行为的来由；当前增量见§5、§6，不把下面“没有的”当作0.1.15状态。

- **主题：**`DeviceState.kt` 里 `Theme { LIGHT, DARK, NIGHT }`；阈值里的 `mode` 是 `auto`（环境光）、`sun`（日出日落）、`light`、`dark`，夜间是另一个开关（`nightEnabled`）。**`docs/04` §9 的表只写了 auto / light / dark，代码里还有 `sun`，以代码为准，文档要补。**
- **进入红移：**环境光 < 5 lux 持续 10 秒；退出：> 15 lux 持续 10 秒。LIGHT 和 DARK 之间至少隔 120 秒；用户在交互（ENGAGED）时推迟切换；传感器失效时按时间兜底（07:00–19:00 浅色，其余深色，**夜间关闭**）（`docs/04` §1.1）。
- **红移的效果：**DARK 之上整屏红色单色、背光压到最低；照片页自动切回时钟页；`level=urgent` 的通知不受红色滤镜影响；过渡 1.5 秒（`docs/04` §1.2、§7）。
- **日出日落：**`DaylightProbe.isDay()` 用和日历同一条地平线；**时钟不可信（早于 2020-01-01，设备没有 RTC）时返回 null**，调用方退回环境光。`Sun` 和 `AstroHost` 能给出每天的日出、日落和晨昏蒙影。
- **注意力：**`ASLEEP` 是“无人一段时间后”，亮度固定在 3%，**屏幕从不熄灭，只调暗**（`docs/03`）。窗口亮度被夹在 ≥ 3%：`screenBrightness = value.coerceIn(0.03f, 1f)`（`MainActivity.kt`）。
- **传感器：**`SensorController` 注册光线和接近传感器（VCNL4200），每秒评估一次。
- **没有的：**睡眠模式、定时、手动切换入口；设置只有 `number`、`bool`、`choice`、`text` 四种控件，**没有“时刻”控件**。
- **设备没有电源键**（`qpnp_pon` 的 `KEY_POWER` 没接线）。所以熄屏之后只能靠触摸或接近传感器唤醒：**“完全不显示”必须是“背光关掉、触摸照常工作”，不能是系统息屏。**

## 3. 三种模式的效果

本表是完整目标。当前睡眠仅使用逻辑 `SLEEP`、`Theme.NIGHT` 和不低于3%的窗口亮度，并接静音/拒绝；全黑、触摸偷看、通话和蓝牙联动尚未完成相应人工验证或开发。

| | 白天 | 红移 | 睡眠 |
|---|---|---|---|
| 屏幕 | 浅色或深色，现有规则 | 深色加红色单色滤镜 | **全黑，背光 0，不画任何东西** |
| 亮度 | 现有（`display.brightness_max` 与注意力档） | 最低档（现有） | 0 |
| 声音 | 正常 | 不变（提议不强制降音量） | **全部静音**：ThinkOS 的媒体暂停；新的播放请求被拒绝 |
| 投屏 | 可用 | 可用 | 新会话拒绝，已有的结束 |
| 通话（`44`） | 可用 | 可用 | 来电静默拒绝（对方收到“忙”），不亮屏 |
| 蓝牙音箱（`46`） | 可用 | 可用 | 不可被发现、不接受新连接；已连接的静音并暂停 |
| 通知 | 正常 | `urgent` 不受滤镜影响（现有） | **一律不响不亮，没有例外** |
| 更新 | 照常 | 照常 | 照常，睡眠时段正好适合安装 |
| 触摸 | ENGAGED（现有） | ENGAGED，不改变模式 | 双击“偷看”（§4.3） |

## 4. 怎么切换

### 4.1 输入

1. **手动：**控制面板（顶边下拉）里两个开关，红移和睡眠。设置页编辑触发方式、时间表与保持策略，不新增另一套手动入口。
2. **睡眠时间表：**用户设置的开始和结束时刻。
3. **日落日出：**位置设置加 `Sun`，不联网。
4. **环境光：**光线传感器。
5. **触摸：**交互状态和唤醒手势。

### 4.2 优先级与规则

1. **手动覆盖最高。**默认保持到“下一个自动切换点”（睡眠结束、日落、日出里最近的一个）；设置里可选“一直保持，直到再次手动切换”。手动覆盖**不跨重启**。
2. **睡眠时间表：**开关打开、时间可信、现在落在 [开始, 结束) 里就进入睡眠，可以跨午夜。开始时如果正在交互（ENGAGED），**推迟到空闲，最长 10 分钟**（提议）。结束时回到红移或白天，由下面的规则再判断，不直接全亮。
3. **红移：**触发方式四选一：**日落到日出**（默认，需要位置）、仅环境光、固定时间、关闭。
   - **日落到日出、固定时间：**窗口内，环境光低于“进入”阈值才进入，高于“退出”阈值才退出。进入用现有的 `theme.dark_below_lux`（50 lux），退出用 `theme.light_above_lux`（120 lux），持续 30 秒（提议）。意思是：晚上房间暗下来就变红，开了房间的灯就回到正常的深色。
   - **“很暗”规则（除“关闭”外都适用）：**环境光 < 5 lux 持续 10 秒进入，> 15 lux 持续 10 秒退出，即现在的行为。白天拉上窗帘也会变红。
   - **没有位置、时间不可信：**日落日出窗口不可用，退回“仅环境光”。
   - **传感器失效：**窗口有效时按窗口进入；没有窗口就不进入（沿用现状）。
4. **白天：**其余时间，LIGHT 和 DARK 照旧。
5. **防抖：**自动切换之间至少隔 120 秒（沿用）；ENGAGED 时推迟自动切换，最长 10 分钟（提议）；手动不受限制。
6. **时间不可信（开机后头一两分钟）：**不按时间表、不按日落日出，只用环境光，**不会自动进入睡眠**。
7. **极昼极夜**（没有日出或日落）：退回固定的 19:00–07:00（沿用现有兜底）。夏令时和跨日由现有的 `Zones.home()` 处理。
8. **重启：**模式不持久化，重启后重新计算。

### 4.3 触摸（用户的触觉使用）

- **白天、红移：**触摸就是 ENGAGED（现有），**不改变模式**；ENGAGED 期间推迟自动切换。
- **睡眠：**屏幕全黑；**双击**任意处“偷看”：显示红移时钟 10 秒，最低亮度，没有别的内容，第一次触摸不传给界面。偷看时点一下“结束睡眠”（只有一个按钮，不加说明文字）退出睡眠，等于手动覆盖，保持到下一个切换点。
- **防误触：**默认要双击；设置可改为“单击”或“关闭”（关闭后只有控制面板的手动开关和时间表能结束睡眠，但黑屏时控制面板也看不见，所以“关闭”要慎用，见 §10）。
- **接近传感器（挥手）：**睡眠中默认关，可选。猫和翻身会误触发；VCNL4200 的有效距离没有实测（`docs/02`）。
- **不做：**学习用户作息、手势识别。

### 4.4 过渡

- 白天与红移之间：1.5 秒（现有，颜色矩阵插值加亮度缓降）。
- 进入睡眠：背光约 3 秒缓降到 0，内容同时淡出（提议）。
- 离开睡眠：先到红移的最低亮度，1.5 秒，**永不一下子全亮**。
- 时钟优先（ADR-029）：过渡只动根层滤镜和亮度，不重建 View。

## 5. 设置与界面（ADR-017、ADR-044）

新增一级分类“模式”（图标 `moon-star`，见 `36` 的 SET-07）。标签 ≤ 12 字，不加说明：

| 键 | 类型 | 值 | 默认 | 标签 |
|---|---|---|---|---|
| `redshift.trigger` | choice | `sun`日落到日出 / `lux`仅环境光 / `fixed`固定时间 / `off`关闭 | `sun` | 红移 |
| `redshift.start`、`redshift.end` | **time（新）** | HH:mm，5 分钟一档 | 19:00 / 07:00 | 红移开始 / 红移结束；只在“固定时间”时出现 |
| `sleep.enabled` | bool | — | **关** | 睡眠 |
| `sleep.start`、`sleep.end` | **time（API10）** | HH:mm，5分钟一档 | 23:00 / 07:00 | 睡眠开始 / 睡眠结束；只在睡眠打开时出现 |
| `sleep.wake` | choice | `double`双击 / `single`单击 / `off`关闭 | `double` | 触摸唤醒；睡眠启用时显示，偷看仍待MODE0 |
| `mode.manual_hold` | choice | `next`到下一个切换点 / `forever`一直保持 | `next` | 手动切换保持 |

以上8个可见字段与以下9个隐藏字段共17个schema键；运行时不另存阈值或时间默认值。极地、故障时段也使用同一 `time` 类型：

| 隐藏键 | 类型 / 范围 | 默认 |
|---|---|---|
| `mode.minimum_switch_s` | number，0–3600秒，步长1 | 120 |
| `mode.engaged_delay_s` | number，0–3600秒，步长1 | 600 |
| `sleep.start_delay_s` | number，0–3600秒，步长1 | 600 |
| `redshift.dark_dwell_s` | number，0–300秒，步长1 | 10 |
| `redshift.window_dwell_s` | number，0–300秒，步长1 | 30 |
| `redshift.polar_start` / `redshift.polar_end` | time | 19:00 / 07:00 |
| `theme.fallback_start` / `theme.fallback_end` | time | 07:00 / 19:00 |

- **旧设置：**逐 `local` / `server` 层迁移：同层合法 `redshift.trigger` 优先，否则旧 `theme.night=false`→`off`、`true`→`sun`，随后删除该层旧bool。这样本地旧值仍高于Server新值，重置新trigger后不会再次迁移。隐藏兼容读由 `trigger != off` 派生，旧写入映射新键，不保存第二份模式值；新装没有旧存值时不因迁移写盘。`theme.mode` 的 `auto/sun/light/dark` 仍留在“显示”。
- **`time` 控件：**API10登记，值严格为ASCII `HH:mm`、00:00–23:55、5分钟一档。原生编辑使用32sp数值和18sp标签/按钮，不依赖键盘；取消、Back、Home或离页丢弃草稿，确定最多提交一次。4对开始/结束允许跨午夜，拒绝相等。
- **控制面板（ADR-035）：**六个quick按3列×2行显示：Wi-Fi、静音、红移（`sunset`）、睡眠（`moon`）、设置、应用。红移/睡眠点按为手动覆盖，关闭切回 `day`，保持策略读 `mode.manual_hold`。
- **插件：**API10 `tos.device.mode()` 无权限只读，返回小写 `day/redshift/sleep`；无权限要求的 `mode(value)` 事件报告相同小写值。普通插件不能改模式；`tos.device.setMode(value)` 仅实际获权的出厂 `system.device` 插件可在5秒内真实OS点按或原生布尔 `form.change` 后调用，挂起返回 `true` 或 `nil,err`，执行前再次核对。Lua不能伪造交互时间，也不能传持续时间或自动参数。
- **引导：**不新增屏。位置和时区引导已有，默认值足够。

## 6. 与其它功能的关系

- **媒体（`MediaEngine`）：**进入睡眠就暂停，睡眠中 `tos.media.load` 返回错误；退出后**不自动继续播放**，音量恢复到进入前的值。
- **统一的“静音”：**当前逻辑睡眠已接媒体/投屏入口，系统1–5音量流作为兜底。先原子保存 `files/state/sleep-audio` 恢复记录，再写0；退出或新进程恢复时只恢复仍为0的自有流，保留用户新的非0值，部分失败保留记录重试。记录是OS恢复状态，不是插件设置。**不碰系统的免打扰策略**；真机本轮验收未完成，不能据主机测试宣称已恢复所有实际路由。
- **投屏、通话、蓝牙：**当前睡眠已接投屏新会话拒绝与已有会话结束；通话、蓝牙联动仍属MODE-4，不能从系统音量兜底推导它们已完成。
- **更新（`docs/34`）：**安静时段对齐睡眠时段。
- **电源保护（`docs/40`）：**不受影响。

## 7. 实现要点

- **`core/ModeController.kt`：**纯逻辑。输入：时钟、lux、`Sun`、手动状态、触摸事件；输出：`Mode` 和下一次需要评估的时刻。主机单元测试用表驱动。
- **接入点：**`SensorController` 驱动模式，主题红移沿用 `NIGHT`；当前睡眠也暂映射 `NIGHT`，亮度下限仍为3%。`SleepPlaybackGate` / `SleepAudioGate` 接静音与拒绝；`MainActivity` 黑屏/偷看效果须等MODE0人工验证，尚未作为已实现效果交付。
- **“完全不显示”要先验证。**窗口亮度被夹在 ≥ 3%，0 能不能真的关掉背光，这台设备没测。候选做法：
  - (a) 窗口亮度 0。
  - (b) 系统层模块里的 root 守护进程写 `/sys/class/leds/lcd-backlight/brightness`（这个节点存在，`powerd` 的灭背光已经是这个写法，见 `docs/40`）。
  - (c) **不用**整屏息屏：面板和触摸共用复位，关面板可能同时丢掉触摸（来自第三方的硬件分析，没验证）。
- **时间不可信期间**（开机后头一两分钟）不按时间，沿用现有规则。

## 10. 风险

| 风险 | 缓解 |
|---|---|
| 背光 0 不是全黑，或者要靠关面板，触摸随之失效 | MODE-0 先验证，有 (b) 备选；**触摸在黑屏下不可用就不能上线睡眠**，否则设备会“死”在黑屏里，只能拔电 |
| 误触唤醒（宠物、小孩） | 默认双击；可选关闭，但关闭后黑屏下没有可见的结束办法，要慎用 |
| 环境光传感器被遮挡或贴近灯，红移误进误出 | 迟滞加持续时间；窗口门控 |
| 断电重启后时间不对 | 时间不可信期间不按时间；重启后默认白天，校时完成后重算 |
| “睡眠”和 `ASLEEP` 撞词 | OWN-25 改标签；内部状态名不动 |
| 睡眠中收不到来电，用户有例外需求 | 默认没有例外；将来加闹钟、来电例外要单独定（OWN-26） |
| `urgent` 通知的现有例外和“完全免打扰”冲突 | 睡眠没有例外 |
