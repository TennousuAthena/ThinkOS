# ThinkOS 企划书 v0.2

> 桌面 AI 伴侣终端 · Kiosk 主应用 · 插件化架构
> 目标设备：Lenovo ThinkSmart View CD-18781Y（Android 8.1 / API 27 / armv7 / 2GB）
> 主算力：macOS 主机

## 0. 形态定义

ThinkOS 不是"一个 app"，而是**这台设备的操作系统外壳（Kiosk Shell）**：

- 开机自动进入，接管桌面（注册为 HOME Launcher）
- 全屏沉浸，无状态栏、无导航栏、无多任务
- 设备端只负责**渲染 + 采集**（屏幕、摄像头、麦克风、扬声器）
- 所有"大脑"跑在 macOS 上（LLM、STT、TTS、插件、数据）

一句话：**设备是显示器 + 传感器 + 音箱，Mac 是主机。**

## 1. 架构

```
┌─────────────── ThinkSmart View (Android 8.1) ───────────────┐
│  ThinkOS Shell (Kotlin)                                   │
│  ├─ 渲染层：卡片组件库（Text/Image/List/Player/Chart）        │
│  ├─ 动效层：Lottie + 自绘粒子（待机/聆听/思考/回应）          │
│  ├─ 采集层：Camera2（手势）、AudioRecord（语音）              │
│  ├─ 输出层：ExoPlayer（音乐）、AudioTrack（TTS）              │
│  └─ 通信层：WebSocket（双向）+ 断线重连                       │
└──────────────────────────┬──────────────────────────────────┘
                           │ Wi-Fi（局域网，毫秒级）
┌──────────────────────────┴──────────────────────────────────┐
│  ThinkOS Core (macOS, Python/Node)                        │
│  ├─ 会话引擎：唤醒→STT→LLM→TTS 编排                          │
│  ├─ 插件宿主：每个插件一个进程/协程，独立沙箱                │
│  ├─ 数据源：日历、天气、音乐库(Navidrome)、相册、通知中转     │
│  └─ 状态机：待机/聆听/思考/回应/提醒（下发给设备驱动动画）    │
└─────────────────────────────────────────────────────────────┘
```

**为什么这样切**：A53 + 2GB 跑不动本地模型；把所有逻辑放 Mac 后，设备端只剩 UI 线程和音视频管线，动画才能优先保证帧率。

## 2. UI 规范（清亮 · 扁平 · 动效优先）

### 视觉

| 项 | 规范 |
|---|---|
| 底色 | `#F7F8FA`（浅灰白，不用纯白，避免 LCD 刺眼） |
| 卡片 | `#FFFFFF`，圆角 24dp，无边框，阴影极浅（2dp, 8% 黑） |
| 主色 | 单色强调（建议柔和蓝紫 `#5B7CFA`），不超过 2 个强调色 |
| 字体 | 系统无衬线，标题 32–40sp，正文 18sp，时间数字等宽 |
| 图标 | 线性 2dp，圆角端点 |
| 留白 | 外边距 24dp，卡片间距 16dp |
| 禁止 | 渐变背景、模糊、拟物阴影、多层嵌套卡片 |

### 动效（第一优先级）

| 状态 | 动画 | 时长/缓动 |
|---|---|---|
| 待机 | 缓慢呼吸（缩放 0.98↔1.02）+ 微光扫过 | 4s 循环，ease-in-out |
| 唤醒 | 中心扩散波纹 + 缩放回弹 | 400ms，ease-out |
| 聆听 | 声波条随音量起伏 | 实时，60fps |
| 思考 | 三点循环呼吸 / 粒子汇聚 | 循环 |
| 回应 | 轻弹跳 + 文字逐字浮现 | 300ms + 40ms/字 |
| 提醒 | 从边缘滑入 + 轻微震动（无马达则用亮度脉冲） | 350ms |

**动画性能预算（硬约束）**
- 目标 60fps，单帧 CPU 绘制 < 12ms
- 同时播放的 Lottie ≤ 3 个，总图层 ≤ 40
- 呼吸类循环动画走 GPU（`setLayerType(HARDWARE)`）
- 禁用 `blur`、大面积 `shadow`、`alpha` 嵌套动画
- 掉帧自动降级：> 45fps 持续 3s → 降低动画帧率/简化图层

## 3. 插件系统（"开源小爱"的核心）

**设计原则：插件跑在 Mac，设备只渲染。** 这样：
- 设备零性能负担
- 插件天然沙箱（不同语言都能写）
- 插件崩溃不影响设备

### 插件包结构

```
plugins/weather/
├── manifest.json      # 元信息
├── main.py            # 逻辑入口
└── assets/            # 图标、图片
```

### manifest.json

```json
{
  "id": "weather",
  "name": "天气",
  "icon": "assets/icon.png",
  "size": "2x1",
  "refresh": 600,
  "actions": ["refresh", "open"],
  "capabilities": ["ui.card"]
}
```

### 渲染协议（下发给设备的 JSON）

```json
{
  "type": "card",
  "id": "weather.today",
  "layout": "flat",
  "children": [
    { "type": "text", "value": "26°", "size": "display" },
    { "type": "text", "value": "多云 · 湿度 62%", "size": "body" },
    { "type": "icon", "name": "cloud", "color": "accent" }
  ]
}
```

设备端只有一套**固定组件库**（text / image / list / icon / progress / player），插件通过 JSON 组合它们。这样既统一了扁平风格，又保证了性能。

### 事件回路

```
设备点击卡片 → {"action":"weather.open"} → Mac 插件处理 → 返回新的 card JSON → 设备渲染
```

## 4. 基础功能（MVP 卡片）

| 模块 | 设备端 | Mac 端 |
|---|---|---|
| 时钟 | 本地渲染，每秒 tick，不依赖网络 | 可下发天气/日程 |
| 相册 | 全屏轮播，淡入淡出 | 扫描照片目录，推缩略图流 |
| 语音助手 | 唤醒词 + 录音 + 播放 | STT + LLM + TTS + 记忆 |
| 音乐播放器 | ExoPlayer + 封面 + 进度 | Navidrome 提供流媒体与元数据 |
| 通知 | 滑入卡片 + 音效 | 接收手机/服务推送并转发 |

## 5. Kiosk 接管方案

| 层级 | 做法 | 效果 |
|---|---|---|
| L1 | 注册 HOME intent，设为默认桌面 | 开机进入，HOME 键回来 |
| L2 | `startLockTask()`（无 device owner 时是"应用固定"） | 阻止退出 |
| L3 | `dpm set-device-owner` 设设备所有者 | 可禁用状态栏、锁屏、按键，真正 COSU |
| L4 | Magisk/Vector 模块 | 系统级 UID 定制（备用） |

**建议走到 L3**：设备是干净的系统，可以直接用 `adb shell dpm set-device-owner` 设为设备所有者，之后：
- `setLockTaskPackages` 白名单
- `setStatusBarDisabled(true)`
- `setKeyguardDisabled(true)`
- 防止卸载、防止改设置

⚠️ 风险：设成 device owner 后要卸载 app 得先移除管理员，需要留恢复脚本（adb 命令写进文档）。

## 6. 横竖屏

- 设备有加速度计（BMA253），支持自动旋转
- 布局用两套资源：`res/layout/`（竖）与 `res/layout-land/`（横）
- 卡片网格：竖屏 2 列、横屏 3 列
- 动画在旋转时**不重放**，用 `onConfigurationChanged` 平滑重排
- 可加设置项：锁定方向 / 跟随重力

## 7. 里程碑（按新形态调整）

| 周 | 交付 |
|---|---|
| W1 | Shell 骨架：HOME 接管 + 全屏 + 时钟卡片 + 呼吸动画 |
| W2 | Mac 端 Core 骨架 + WebSocket 协议 + 卡片渲染引擎 |
| W3 | 插件宿主 + 天气/相册两个示例插件 |
| W4 | 语音链路（唤醒→STT→LLM→TTS）+ 动效状态机 |
| W5 | 音乐播放器（Navidrome）+ 通知中转 |
| W6 | 手势（如帧率达标）、稳定性、横竖屏打磨 |

## 8. 风险与缺口

1. **动画 vs 性能**：A53 上 Lottie 大面积矢量动画可能掉到 30fps → 必须在 W1 就做帧率基准测试，确定可用的动画复杂度上限
2. **Kiosk 的自救能力**：如果 app 崩溃，用户会卡在黑屏 → 必须做"看门狗"（前台服务 + 系统重启兜底 + adb 恢复脚本）
3. **插件协议过早僵化**：组件类型一旦定死，后续扩展困难 → 建议 MVP 只定 5 种组件，留 `custom` 扩展位
4. **局域网依赖**：Mac 关机/睡眠时设备变砖头 → 需要"离线模式"（时钟、相册、本地音乐可用）
5. **单麦远场**：语音交互距离限定 1 米内
6. **相册隐私**：照片推流要注意不要缓存明文到设备

## 9. 待你拍板的三件事

1. **插件用什么语言写**？Python（你 Mac 上最方便）还是 JS/TS？
2. **Mac 端 Core 用常驻服务还是菜单栏 app**？前者稳定、后者好控制。
3. **设备掉线时的默认界面**：显示时钟+相册（可用），还是显示"连接中"？
