# ThinkOS 企划书 v0.1

> 一台常驻桌面的 AI 伴侣终端 · 目标设备：Lenovo ThinkSmart View CD-18781Y

## 1. 一句话定位

把一台 8 英寸的退役 Teams 会议屏，改造成一台**永不熄屏的桌面 AI 伴侣**：它能看见你（手势）、听见你（语音）、主动提醒你（通知/日程），并用有情绪的动画回应你。

## 2. 目标场景（只做这三个）

| 场景 | 用户行为 | 系统响应 |
|---|---|---|
| 问答 | 说唤醒词 + 提问 | 动画进入"聆听"→ 回答 + TTS |
| 手势控制 | 挥手/举手/握拳 | 音量、静音、翻页、打断 |
| 被动提醒 | 无操作 | 收到推送 → 动画 + 提示音 |

## 3. 硬件基线（已实测确认）

| 项目 | 实测值 | 对设计的约束 |
|---|---|---|
| SoC | APQ8053，8×Cortex-A53 @1.8GHz | 只能跑轻量模型 |
| GPU | Adreno 506 | 2D 动画够用，3D 勉强 |
| RAM | 2GB（可用约 700MB） | 单进程预算 ≤ 400MB |
| 存储 | /data 3.8GB，可用 3.7GB | 够装 app + 缓存 |
| 屏幕 | 800×1280 竖屏渲染 | 竖版布局（可转横） |
| 系统 | Android 8.1 / API 27，userdebug | 无 GMS、无 FCM 推送 |
| ABI | 仅 armeabi-v7a | 所有依赖必须有 32 位 so |
| 摄像头 | S5KC505A，Android 下可用 | 无 Linux 驱动，只能用 Android |
| 音频 | 麦克风 + TAS5782M 扬声器 | 单麦，远场拾音一般 |
| 供电 | 无电池、无 RTC、常插电 | 时间靠开机校时（已解决） |
| 权限 | 已 root（Magisk 27 + Vector API 102） | 能做系统级定制 |

## 4. 功能规划

### MVP（4–6 周）

1. **常驻界面**：Lottie 驱动的呼吸/情绪动画，全屏沉浸
2. **语音链路**：唤醒词 → 录音 → 云端 STT → LLM → TTS → 播放
3. **手势**：MediaPipe HandLandmarker，识别 3 个手势（举手/左右挥/握拳）
4. **通知**：WebSocket 接收后端推送 → 动画 + 音效
5. **常驻**：前台服务 + 开机自启 + 断电恢复

### V1

- 人脸检测（有人靠近自动唤醒屏幕）
- 多轮对话上下文（本地 SQLite 存最近 N 轮）
- 日程/天气/音乐控制
- TTS 音频本地缓存

### V2（需重新评估硬件）

- 视觉问答（拍照 → 多模态模型）
- 自定义手势训练
- 主动行为（根据时间/场景主动说话）

## 5. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 语言/UI | Kotlin + View 体系 + Lottie | Compose 在 A53 上偏重，View 更稳 |
| 相机 | Camera2 + ImageReader | 比 CameraX 轻，控制更细 |
| 视觉 | MediaPipe Tasks 1.2.0 | 已验证含 armeabi-v7a |
| 唤醒词 | Picovoice Porcupine | 已验证含 armeabi-v7a，离线免费额度 |
| 离线 STT | Vosk 0.3.47（兜底） | 已验证含 armeabi-v7a |
| 网络 | OkHttp + WebSocket | 断线重连 + 心跳 |
| 音频 | AudioRecord 16k mono + AudioTrack/ExoPlayer | 语音标准链路 |
| 后端 | Mac 上跑 Python/Node 服务 | 开发快，局域网延迟低 |
| LLM | 云端 API | 2GB 内存跑不了本地模型 |
| 系统定制 | Magisk + Vector | 沉浸模式、系统 UI 定制 |

## 6. 数据流

```
[唤醒词常驻] ──命中──> [录音 3s 环形缓冲] ──> [STT 云端] ──> [LLM]

[Camera2 320×240] ──> [MediaPipe Hands] ──> [手势事件] ──┼──> [状态机]
                                                       │
[WebSocket 通知] ──────────────────────────────────────┘
                                                       │
                              [Lottie 动画 + TTS 播放 + 音效]
```

## 7. 缺口清单（我认为你的想法目前缺什么）

1. **没有定义"记忆"**：伴侣感来自上下文记忆。需要明确存什么（最近对话、你的偏好、日程）、存哪里（本地 SQLite / 云端）、保留多久。
2. **没有定义内容源**：日程、消息、天气、待办从哪来？这决定推送链路。
3. **没有定义隐私边界**：摄像头常开、语音上传云端，用户能否接受？需要明确"本地处理 vs 云端"。
4. **没有定义失败策略**：断网、云端超时、识别失败时，界面说些什么？这决定体验下限。
5. **没有定义唤醒词与误触发策略**：误触发会让人很快关掉设备。
6. **远场拾音是硬伤**：单麦克风，1.5 米外识别率会明显下降，需要明确"使用距离"（建议 1 米内）。
7. **手势的物理边界**：8 寸屏在桌面，摄像头视角约 60°，有效手势区在 40–80cm、正面 ±30°；低光下会失效。

## 8. 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 手势帧率不达标 | 交互卡顿 | 降到 256×256、跳帧、只跑 3 个手势 |
| 2GB 内存 OOM | 崩溃 | 单进程、复用 bitmap、限制模型数量 |
| 唤醒误触发 | 体验崩塌 | VAD 双阈值 + 冷却时间 |
| 云端延迟 >2s | 对话不自然 | 流式 TTS、本地先说"嗯" |
| 8.1 老系统兼容坑 | 开发受阻 | 先做技术验证 spike |

## 9. 里程碑

| 周 | 交付 |
|---|---|
| W1 | 可运行骨架：全屏动画 + 前台服务 + 开机自启 |
| W2 | 语音链路打通（唤醒→STT→LLM→TTS） |
| W3 | 相机 + 手势识别跑通，实测帧率 |
| W4 | 通知/提醒链路 + 状态机整合 |
| W5 | 稳定性：内存、断线、72 小时连续运行 |
| W6 | 打磨：动画、音效、开机流程 |

## 10. 成功度量

- 唤醒率 > 90%，误触发 < 1 次/小时
- 语音指令端到端 < 1.5s（不含云端）
- 手势识别率 > 85%（40–70cm，正常室内光）
- 连续运行 72 小时不重启、不 OOM

## 11. 明确不做

- 不做本地大模型
- 不做 WebView 界面
- 不做视频通话
- 不做多用户/多设备同步

## 12. 本周就能做的三件事

1. 搭骨架 APK：全屏 + Lottie 待机动画 + 前台服务
2. 真机验证 MediaPipe 手势帧率（这决定产品形态）
3. 确定后端接口格式（WebSocket 消息 schema）
