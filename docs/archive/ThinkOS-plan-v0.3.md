# ThinkOS 企划书 v0.3

> **定位重构：从"AI 伴侣"降级为"桌面智能终端"**
> 核心资产：8 寸屏 + 摄像头 + 扬声器
> 目标设备：Lenovo ThinkSmart View CD-18781Y（Android 8.1 / armv7 / 2GB）

## 0. 一句话定位（新版）

> 一块**好看、会动、能听会看**的桌面屏幕。
> 语音助手是可选配件，不是主角。

**价值观转变**：不再试图让这台 A53/2GB 的机器"理解你"，而是让它**好看地显示信息、敏锐地感知环境、靠谱地播放声音**。这三件事它确实做得好。

## 1. 三条主线与权重

| 主线 | 权重 | 说明 |
|---|---|---|
| **显示** | 50% | 动画、信息卡片、相册、可视化 |
| **音频** | 30% | 音乐、白噪音、音量/均衡、频谱 |
| **视觉** | 20% | 存在感知、手势、镜像/滤镜 |
| 语音 | 可选 | 只保留"唤醒词 + 少量固定指令" |

## 2. 功能矩阵

### MVP（3–4 周）

**显示**
- 常驻待机界面：呼吸动画 + 时钟 + 天气
- 全屏相册：Ken Burns 缓动 + 淡入淡出切换
- 卡片系统：时钟、天气、相册、音乐、通知

**音频**
- 音乐播放器：Navidrome 拉流（已实测服务器可用）
- 封面 / 进度 / 播放队列卡片
- **音乐频谱可视化**（显示 + 音频的核心结合点）

**视觉**
- 存在感知：摄像头 1fps 检测人脸 → 有人亮屏 / 无人降亮度
- 手势（低频）：挥手唤醒、左右切换卡片、握拳静音

**系统**
- Kiosk 接管（HOME Launcher + 沉浸）
- 开机自启、断线重连、断电恢复

### V1
- 白噪音 / 环境音（睡眠场景）
- 通知卡片（手机 → Mac → 设备）
- 定时拍照 / 延时摄影
- 相册智能轮播（按人物/时间）
- 音量与均衡调节（配合已装的 ViPER）

### V2
- 视觉特效（镜像、黑白、时间切片）
- 手势自定义
- 语音作为可选模块接入（不默认开启）

## 3. 语音功能降级说明

**保留**：唤醒词 + 5 个固定指令（"停止播放"、"下一首"、"静音"、"打开相册"、"现在几点"）
**砍掉**：多轮对话、LLM 闲聊、语音问答、语音日程

理由：
- 单麦克风远场拾音差，1 米外就不稳
- 2GB 内存跑完整语音链路（VAD+STT+LLM+TTS）会和 UI 抢资源
- 相比"能聊天"，用户对"好看 + 好听"的感知更强

## 4. 摄像头三档策略（省算力的关键）

| 档位 | 用途 | 频率 | 功耗 |
|---|---|---|---|
| L0 常驻 | 存在检测（有人/无人） | 1 fps | 极低 |
| L1 按需 | 手势识别 | 10 fps，仅在检测到人后开启 | 中 |
| L2 手动 | 拍照/延时 | 用户触发 | 短时 |

**关键决策**：手势不再常开，改为"检测到人 + 最近有交互"才开启，10 秒无交互自动回到 L0。这样 CPU 占用从持续 ~40% 降到平时的 ~5%。

## 5. 架构（Mac 端职责收缩）

```
设备端（Android）
 ├ 渲染：卡片组件 + Lottie + 频谱自绘
 ├ 视觉：Camera2（L0/L1/L2 三档）
 ├ 音频：ExoPlayer + AudioRecord（仅唤醒词）
 └ 通信：WebSocket
        ↕
Mac 端（轻量服务）
 ├ 媒体库：Navidrome（音乐）、照片目录（相册）
 ├ 数据：天气、日程、通知中转
 └ 逻辑：插件宿主（卡片数据计算）
```

变化：Mac 端**不再需要跑 LLM/STT/TTS**，只做内容与数据服务。这意味着 Mac 端可以极简（甚至一个 Python 脚本 + Navidrome）。

## 6. UI 与动效（延续 v0.2）

- 底色 `#F7F8FA`，白卡片 24dp 圆角，无阴影堆叠
- 主色 `#5B7CFA`，最多 2 个强调色
- 时间等宽大数字 40sp
- 动画预算：60fps / 单帧 <12ms / Lottie ≤3 个同时

**新增：音乐可视化规范**
- 频谱条：64 根，底部对齐，圆角 2dp
- 用 `Visualizer` API 或 FFT（AudioRecord 分轨）取频谱，自绘 Canvas
- 60fps 目标，降级到 30fps 时减少条数

## 7. 性能预算

| 指标 | 目标 |
|---|---|
| 待机 CPU | < 8% |
| 播放音乐 + 可视化 | < 25% |
| 手势模式（L1） | < 45% |
| 内存峰值 | < 350MB |
| 连续运行 | 72 小时不重启 |

## 8. 里程碑（缩短到 4 周 + 打磨）

| 周 | 交付 |
|---|---|
| W1 | Shell 骨架：Kiosk 接管 + 时钟卡片 + 呼吸动画 + 帧率基准 |
| W2 | 相册（Ken Burns）+ 音乐播放（Navidrome） |
| W3 | 音乐频谱可视化 + 卡片切换动效 |
| W4 | 摄像头 L0 存在感知 + L1 手势 + 稳定性 |
| W5 | 通知卡片、白噪音、打磨 |

## 9. 风险（重新排序）

| 风险 | 等级 | 缓解 |
|---|---|---|
| 动画在 A53 上掉帧 | 高 | W1 先做帧率基准，定动画复杂度上限 |
| 频谱可视化吃 CPU | 中 | 降采样、减少条数、必要时 30fps |
| 摄像头低光失效 | 中 | 存在检测用降分辨率 + 提高 ISO；必要时加补光 |
| Mac 依赖 | 中 | 离线模式：时钟/相册/本地音乐可用 |
| Kiosk 崩溃黑屏 | 中 | 看门狗 + adb 恢复脚本 |
