## 希望用户怎样听歌

打开「媒体」，看到《Carefree》和一组可以马上播放的歌。点《Carefree》，音乐开始，卡片和底部播放条显示正在播放。用户可以继续向下选歌，点播放条才展开大播放器。查看接下来会播什么、换一首，再返回时，刚才看到的歌曲仍在原处。

现有原应用已经用真实录音验证过浏览、解码、暂停及切歌。当前实机截图里，五个并列标签和「搜索歌曲」占据首屏顶部，八首歌采用相同图标和行高；点歌会跳到全屏，大幅音符占位又占去竖屏的大半。改版先解决这三个具体问题。[现有资料库](../artifacts/features/online-sleep-20261118/device-music-browse-catalogue.png) · [现有播放页](../artifacts/features/online-sleep-20261118/device-music-browse-now-playing.png) · [既有实机验证](../artifacts/features/online-sleep-20261118/device-music-browse.json)

## 从参考产品取什么

| 参考 | ThinkOS 的取舍 |
| --- | --- |
| 用户截图中的主推卡、成组歌曲、底部播放器 | 主推给出一个明确的播放动作，下方留出其它歌曲，底部随时接管播放。针对 ThinkSmart 的可用宽度，横屏用双栏，竖屏用单列。 |
| Apple Music 把精选作品放在发现页顶部，各区有明确的浏览入口 | 首屏展示音源选定的作品。首版按已有目录顺序编排，因为它能解释为什么显示这些歌。见 [Apple 使用指南](https://support.apple.com/en-euro/guide/iphone/iph2c41e6189/ios)。 |
| Spotify 通过底部播放条进入正在播放，再从明确的按钮查看队列 | 迷你条承担暂停和展开，播放页提供看得见的「待播」入口。见 [Spotify 队列指南](https://support.spotify.com/us/article/play-queue/)。 |

## 页面与操作

| 页面 | 内容和布局 | 点按与返回 |
| --- | --- | --- |
| 发现 | 顶部「发现」「资料库」和搜索按钮。首张主推显示曲名、艺人、专辑和播放键；下方「精选歌曲」按源端顺序展示余下曲目。只有一首时只展主推。 | 点卡片或歌曲即播，留在发现页。首次进入且有源时默认发现；同次返回恢复原位置。 |
| 资料库 | 收纳本地音乐、最近播放、视频和网络流。保留已有入口和内容。升级时，旧「在线音乐」映射到发现，明确保存过的本地、视频、最近或串流偏好映射到对应栏目。 | 两次点按内从发现进入本地音乐。仅展示已有记录的最近播放；在线曲目的临时播放链接不写入历史。 |
| 搜索 | 顶部随时可达，提交后复用与发现相同的歌曲行、播放动作和底部条。结果为空时保留查询词及返回入口。 | 点结果即可播放并留在结果页。收起大播放器返回同一批结果；退出搜索回到原浏览位置。 |
| 正在播放 / 待播 | 迷你条固定在内容底部，有会话时显示歌名、艺人、播放/暂停和下一首。展开后显示封面、进度、音量和队列按钮。 | 点条中文字或缩略图展开，点控制键只执行该动作。队列标出当前曲与下一首，点行跳播；返回依次回到播放页和来源页。 |

## 实施顺序与交付

1. **用当前曲库做可点原型。** 先做同一设计的横、竖两版，串起发现 → 点播 → 继续浏览 → 展开 → 待播 → 返回。用《Carefree》展示无图状态，用授权且版本可核实的图片或明确标记的验证样本展示有图状态。用这一版确认首屏密度、点歌是否留页、返回位置。原型中的播放状态只用于体验评审。
2. **落地发现、资料库和搜索。** 复用现有浏览、搜索、按需解析协议，以及本地目录。由播放器插件编排内容，原生视图负责触摸和布局。先核对通用组件能否承载主推与歌行，再决定是否补通用视图能力；如需扩展，同步更新视图契约、安卓和模拟器。文字元数据先呈现，封面按可见尺寸和范围异步加载。无源时提供本地音乐及配置入口，旧源只支持搜索时保留搜索；目录超时允许原地重试。
3. **打通完整播放过程。** 沿用 MediaEngine 的同一会话和队列，统一列表、迷你条、全屏和待播的状态；快速连点以最后一次有效选择为准。选新曲解析失败，当前曲继续，并在被点行反馈。刷新、换源、返回时丢弃过期结果；睡眠期间拒绝新播放，退出后保持暂停。保留系统边缘返回与进度条拖动各自的手势区域。
4. **用原应用做体验验收。** 先用主机与模拟器验证旧偏好迁移、慢源/错误/取消、加载图片、长歌名、RTL 与减少动画，再用 HUA0BWUT 上同包名的 ThinkOS 验证横竖屏、真实录音和连续操作。交付前后同场景截图、操作录像或逐步记录、解码和播放状态。真机性能测量在功能通过后先告知所有者，再按已有时钟和内存预算取数。

## 如何判断改版成功

- 有音源时，横竖屏首屏都能看见可播放的作品。点一次即可起播，停留在当前页面，键盘只在用户主动搜索时出现。
- 用《Carefree》开始播放，浏览到后面的歌曲，展开播放页、进入待播再返回。曲目、进度、滚动位置都正确，过程无重复起播。搜索结果走同一路径也成立。
- 更换曲目时，主推、歌行、底部条、全屏和队列一致显示当前曲。旧封面晚到、解析失败或旧搜索回包时，界面继续对应用户最后一次操作。
- 真实封面、无图、断网、未配置及旧源分别取证。无图时两种方向都能直接操作播放键；离线仍可进本地音乐。浅色、深色及红移下可辨认当前曲，主要控制热区至少 48dp，文字对比度至少 4.5:1，遵循项目四档字号。
- 按项目已有上限核对单帧绘制 12ms、内存峰值 350MB、同时最多两张大图。持续加载封面时同时观察时钟；必要时优先减少封面加载与转场。模拟器和真机结果分别记录。[ThinkOS 界面与性能规范](04-ui-spec.md)
