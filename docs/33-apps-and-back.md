# 33 · 应用与全局返回手势

> 2026-11-02，ADR-040。**已实现，已在真机上用注入的触摸验证（`nav_back_device.py`，26 项通过）；性能没有测**（见 §8）。
> 标记：**已核对** = 读过代码或跑过脚本；**未验证** = 还没上真机或没测。
> 先读：`AGENTS.md` → ADR-028 / 030 / 035 / 037 / 039 → `29-panel-and-apps.md` §3、§4 → 本文。

## 1. 用户要什么，用户定了什么

1. 除了**卡片**，给插件增加一种新的展现形式：**应用**。默认全屏，进入后左右滑不再切换其它页面。
2. 全局手势：**从最左缘起手向右滑 = 返回键**。
3. 启动应用时有一个 **Windows 8.1 风格的“翻转并启动”动画**。

用户拍板的四件事（2026-11-02）：

| | 决定 |
|---|---|
| 名字 | “程序”和“应用”合并成一个概念，统一叫**应用**（区别于“安卓 App”）。所以 manifest 的 `apps[]` **不改名**，上一版文档里的“程序”一律作废 |
| 实时活动页 | 视频、电视、音频播放页这类接管页也**只靠返回退出** |
| 翻页序列里 | 从最左缘向右滑**照常翻页**，没有死区 |
| 第一批应用 | `player.library`、`iptv.channels`、`cast.home`，三个都要能用 |

## 2. 三种展现形式

| | 卡片 | 页面 | 应用 |
|---|---|---|---|
| 是什么 | 页面里的一块：栈里的卡片、磁贴、Aero 窗口 | 整屏，排在翻页序列里 | 整屏，**不在**翻页序列里 |
| manifest | `widgets[]` | `pages[]` | `apps[]`，指向一个 `pages[]` 里的页面，该页面不能带角色 |
| 怎么进 | 页面带出来 | 左右滑 | 点磁贴或卡片（`opens`）、插件自己的请求（`tos.page.focus`） |
| 左右滑 | 属于页面 | 换页 | **属于应用**：OS 不翻页，连边缘的橡皮筋位移也不做 |
| 上下滑 | 翻栈 / 滚动 | 切变体 | 切变体 / 内容 |
| 怎么出 | — | — | **返回**（最左缘右滑、Back 键）、Home 键，或插件自己 `tos.page.release` |
| 页面指示点 | 有 | 有 | 没有 |

另外几种整屏不算新形式：设置页（`settings` 角色，长按进入）、操作栏（叠层，不是页面）、实时活动（插件接管进入的整屏）。**它们和应用共用同一个返回栈、同一种退出方式。**

## 3. 返回栈（`core/NavStack.kt`，已核对）

原来“返回”散在 `DeckRouter` 的三个字段里（`settingsReturn`、`previousLive`/`livePage`、`previousApp`），嵌套时靠手工复位。现在收成一个纯 Kotlin 的栈，没有任何 Android 依赖，有 JVM 测试（17 项）。

- **层**：`APP`（用户进入的应用）、`TAKEOVER`（插件接管整屏，如放电影）、`SETTINGS`（设置页）。栈底之下是翻页序列里的当前页，第一层压上去时记住，最后一层弹掉时还原，页面和变体都还原。
- **压栈**：`DeckRouter.open`（点磁贴 / 卡片）对 `app` 页、`live` 页，或栈里已经有东西时压 `APP`；`requestFocus(live)` 压 `TAKEOVER`，已有接管时**替换**栈顶（返回仍然回到第一个接管开始的地方）；长按进设置压 `SETTINGS`。其余的“打开某页”（栈空，普通页）还是翻页序列里的一步，不压栈。
- **不重复**：要打开的页已经在栈里，就把它上面的层剥掉（电视的“频道列表”按钮就是这样回到频道页），不叠第二份。
- **出栈**：返回；插件 `tos.page.release`；页面所属插件消失 / 被禁用 / 崩溃时按页清掉（`prune`），栈顶失效就显示下一层，底也失效就回主页；Home 键清空；睡眠、环境页角色出现时清空。
- **深度 ≤ 8**，满了拒绝再进并写日志。
- 设置页仍然拦住一切：它开着时 `open` / `requestFocus` / 翻页都不动，30 秒无操作自动关。

## 4. 返回（已核对）

### 4.1 处理顺序（手势和 Back 键同一条路，`ThinkStage.back()`）

1. 操作栏开着 → 关操作栏。
2. 页面有原生弹层或展开项 → 先收起。Aero 开始菜单与 `FormView` 的时区/地点选择器、展开选项由 `back()` 处理；选择器是表单叠层，文字输入才是安卓对话框。`hasBack` 只查询是否有东西可关闭，手势起手时用于阻止上一层预览。
3. 栈顶是声明了拦截的应用或设置页 → 把 `back` 事件交给它，不弹栈（`BackGate`）。
4. 否则弹栈，回到下一层。
5. 栈空（在翻页序列里）：Back 键什么都不发生；手势则是翻页。

### 4.2 应用与设置页自己接管返回

```lua
tos.back.intercept(true)            -- 我有自己的层级，返回先给我
tos.on("back", function(page)       -- 用户返回时收到；回到根层时把返回交还给系统
  if depth > 1 then depth = depth - 1; render() end
  if depth == 1 then tos.back.intercept(false) end
end)
```

- 不需要新权限；拦截只对栈顶那一层所属的插件起作用，包含 settings 层。设置插件维护 scope 栈：系统到相册再返回先回系统；从天气长按直达时，天气就是栈底。完成仍退出整个设置。
- **页面离开就自动作废**：`page.leave`（被别的层盖住也算）之后要重新声明，回来会收到 `page.enter`。
- **写坏的应用困不住人**：收到 `back` 后 2 秒内毫无反应（没改状态、没调任何 `tos.*` 动作、没交还拦截），下一次返回直接弹栈，并收回拦截。“有反应”只看处理 `back` 那一刻的调用，不看计时器里的更新，所以一个整天刷新状态的插件也躲不过去。纯 Kotlin 的 `BackGate`，时间由参数传入，JVM 测试 9 项。
- 真实用例：`iptv` 打开了一个分组时，返回先回到分组列表，再返回才离开应用。

### 4.3 手势（`BackGesture` + `ThinkStage`）

- **起点**：单指，按下点在物理最左 `nav.back_edge_dp` 内（默认 24dp，16–48，隐藏项），**不随 RTL 镜像**，和翻页一致。**只有栈里有东西时才起作用**；栈空时这条边缘就是普通的翻页起点。
- **判定**：滑过 slop 后，向右且横向占优 = 返回；向左或竖向占优 = 把整段触摸原样交还页面（和操作栏下拉用的是同一套“先扣住、再重放”）。
- **左上角**和操作栏的下拉重叠：谁先超过 slop 谁赢。`BackGesture.classify` 给出 `WAIT / BACK / PULL / PAGE`。
- 第二根手指落下 → 取消，救援手势（双指长按左上 5 秒）不受影响。
- **跟手**：当前页随手指右移，返回目标从左边滑进来（和翻页的邻页一样），左缘随手指高度画一个返回箭头（箭头按界面语言镜像，起手边缘仍是物理最左；舞台的系统层，夜间滤镜自然生效）；过 22% 屏宽，或甩动超过 700dp/s，提交；否则弹簧回位，阈值和弹簧与翻页完全相同。应用/设置声明拦截，或页面有自己的选择器/菜单要关闭时，没有目标可露，页面只做橡皮筋位移，提交后发 `back` 事件。
- 设置：`nav.back_enabled`（默认开，设置页可见）、`nav.back_edge_dp`（隐藏项），11 种语言。

### 4.4 手势总表

| 手势 | 翻页序列里的页面 | 应用 | 设置页 | 接管页（视频、电视） |
|---|---|---|---|---|
| 左右滑（任意处） | 换页 | **归应用** | 归表单 | 归画面（进度条、双击快进） |
| 上下滑（底边条外） | 切变体 / 翻栈 | 切变体 / 内容 | 滚动 | 亮度 / 音量 |
| 从最左缘向右滑 | **照常翻页** | **返回** | **返回（关设置）** | **返回** |
| 从顶缘向下滑 | 操作栏 | 操作栏 | — | 操作栏 |
| 从物理底边向上滑（ADR-045） | 到应用磁贴页，已在该页且栈空时归页面 | 清栈到磁贴页 | 关设置并清栈到磁贴页 | 清栈到磁贴页，视频暂停 |
| 长按 0.6 秒 | 进该页设置 | 进该页设置 | — | 进设置 |
| 双指长按左上 5 秒 | 救援菜单 | 救援菜单 | 救援菜单 | 救援菜单 |
| Back 键 | 无事发生 | 同返回手势 | 同 | 同 |
| Home 键 | 回主页 | 清栈回主页 | 同 | 同 |

## 5. 启动动画：翻转并启动（`ui/AppTransition.kt`，已核对）

Windows 8.1 开始屏启动应用的样子：点中的磁贴按下去，所有磁贴像一排绕左边缘转的门一样翻走，被点的那块最后走，应用页绕同一条边翻进来。关应用时倒着放。

| | |
|---|---|
| 触发 | 路由器给 `DeckState` 带一个 `transition`：`LAUNCH`（打开 `app` 页）、`RETURN`（用 Back 键 / 应用自己关闭 / `tos.page.release` 关应用）、其余 `SLIDE`（照旧）。手势返回已经被手指带着走了，所以用滑动，不再翻一次；接管页和设置页的出入也是滑动 |
| 打开 | 开始屏：标题和每块磁贴绕**自己的左边缘**转到 84°，透明度降到 0，每块 240 ms，间隔 26 ms（最多错开 180 ms），离点按点近的先走，点中的最后走；200 ms 时应用页绕**屏幕左边缘**从 84° 转回 0，320 ms。开始屏自己的背景同时淡出，不会在结束时突然变色。总长约 520 ms |
| 关闭 | 应用页转走；开始屏的磁贴在 90 ms 后转回来，上次点的那块先回；背景同步淡入。总长约 500 ms |
| 不是开始屏 | 没有磁贴的页面（时钟、卡片栈）整页当作一扇门 |
| 词汇 | 角度、时长、顺序都归 OS（ADR-028）：插件只能“打开”或“关闭”应用，不能要别的姿势 |
| 关掉 | 系统动画开关为 0，或 `reducedMotion`：不翻，照旧滑动 / 直接换；手指落下、旋转、另一次导航会**立即**把动画推到终点 |
| 实现 | 全是不带监听器的 `ViewPropertyAnimator`（API 27 可以交给渲染线程），整页另加硬件层，结束只靠一个 `Handler` 回调；唯一在主线程每帧动的是背景淡入淡出（改一个 drawable 的 alpha）。`TileBackdrop` 为此支持了 alpha |

**时钟优先（ADR-029）**：设计上这段动画没有让时钟在主线程多做任何事，翻转期间 `FrameGovernor` 把节拍提到 60，所以时钟页翻走之前秒针不会停；**但没有量化测过**，要先告诉你再跑 `clock_accuracy_device.py`（§8）。

## 6. 三个应用

| 应用 | 页面 | 入口 | 说明 |
|---|---|---|---|
| **媒体** | `player.library` | `player.tile` 磁贴，`player.now` 卡片 | 资料库退出翻页序列；播放时 `player.video` / `player.audio` 是它上面的接管层，返回回到资料库，视频随 `page.leave` 暂停 |
| **电视** | `iptv.channels` | `iptv.tile` 磁贴 | 频道页退出翻页序列；点频道压 `iptv.live`，返回回到频道列表，“频道列表”按钮把它上面的层剥掉；打开分组时返回先关分组 |
| **投屏** | `cast.home`（**新**） | `cast.tile` 磁贴 | 等待页：“投屏到 {设备名}”，DLNA / AirPlay / Miracast 三行（一句设备提示 + 开 / 关；Miracast 开着但系统模块没装时写“缺少系统模块”），底下一句怎么投或为什么找不到。点任何一行去系统设置（插件不能写设置）；从设置回来是新的 `page.enter`，所以看到的是改完的结果。数据来自新的只读 `tos.cast.status()` |

## 7. 对现有行为的改动

ADR-045 另增全局底边上滑：目标由 `launcher` 角色指定（API9、实际system.apps授权），默认是tiles.apps。默认开关 `nav.up_enabled` 在桌面分类，隐藏触发区 `nav.up_edge_dp` 默认24dp（16–48）。候选触摸停住150ms后交还页面，条内点击、长按和横滑保留；向上超过22%屏高或700dp/s提交。拖动只移动当前页和OS箭头，松手提交后以RISE过渡建目标页，关闭动画时直接切。操作栏打开、目标页栈空、安全模式都不接管。导航状态仍只在NavStack。

从安卓页面手动返回时先唤醒再恢复舞台；超时自动回来保持原注意力策略。taskId在onResume记录。APP-7功能分轮17项通过；APP-8接收者优先moveTaskToFront找回原任务，进程丢失记录时才启动MainActivity，模块联动待人工安装1.1并重启。详见37号文档和artifacts/app/APP-7/report.md。

- **实时活动页**（影院视图、电视、音频播放页）和**设置页**改用返回退出，不再靠横滑；影院视图里手指一横滑不会再把正在看的片子退出去。
- `MainActivity.onBackPressed()` 调 `stage.back()`；`DeckRouter` 里三个返回字段删除。
- 应用页、接管页、设置页不画翻页指示点。
- `apps[]` 的页面不能带角色（Python 校验、Kotlin 校验模板同步改，`shared/gen/` 重新生成）；`manifest.json` 里对 `apps` 的说明从“左右滑返回”改成返回。
- 调试广播 `page` 现在从翻页序列出发（栈里有东西时先回主页），和点磁贴一致；原来靠它跳到 `player.library` 的测试照常工作，因为它现在是应用。
- 设备测试：`player_device.py` 两处、`media_ui_device.py` 一处“横滑离开”换成 Back 键；新增 `nav_back_device.py` 和 `fixtures/nav-probe`。
- `cast` 插件 `api` 升到 8；`player` 0.4.0、`iptv` 0.2.0、`cast` 0.2.0、`tiles` 0.3.0。

## 8. 验证与没验证

**已验证（2026-11-02，设备 HUA0BWUT，竖屏 800×1280，ADB 注入的真实触摸与按键）：**

- JVM：全部 581 项，0 失败（新增 `NavStackTest` 17、`BackGateTest` 9、`BackGestureTest` 9；`SystemSettingsVisibilityTest` 加了 `nav.back_enabled`）。iptv 原生 Lua 48 项（新增一项：打开的分组拦截返回），Python 48 项，Go 协议测试，插件打包校验。
- `nav_back_device.py` 26 项全过：翻页序列里 Back 无事发生、最左缘右滑照常翻页；点磁贴打开 `cast.home`，日志 `reason=open`；应用里横滑不换页；最左缘滑一半松手回弹，不从边缘起手的不返回；最左缘滑过阈值回到 `tiles.apps`（`reason=back`）；左上角向右是返回、向下仍是操作栏、Back 先关操作栏；设置页用 Back 和边缘滑都能关；应用叠应用一层一层退；Home 键清栈回 `home.main`；探针应用拦截返回、交还后下一次离开；声明了拦截却不反应的应用 2 秒后被越过；睡眠清栈、醒来回主页。
- 动画：用 `screenrecord` 逐帧看了打开、用 Back 关闭、从时钟页（整页翻）三种。

**没验证 / 没做：**

| | 说明 |
|---|---|
| **性能** | 没跑 `gfxinfo` 十分钟、冷启动、`clock_accuracy_device.py`。按约定先告诉你再跑；动画期间时钟的迟到和跳秒尤其要测 |
| 屏幕最边缘的触摸灵敏度 | 测试从 x=6 起手能触发；更靠外没测。不够就调大 `nav.back_edge_dp` |
| 横屏安装方向 | 设备现在是竖屏。横屏时系统导航栏落在哪一侧、没装 `thinkos-immersive` 时左缘滑动会不会闪出它：没验证 |
| 靠左缘的可拖动控件 | 进度条、滑块、表单行的左缘留白 ≥ 边缘宽度，只看了视频画面和设置页，没逐个量 |
| RTL 语言 | 按“最左”不镜像，没在阿拉伯语 / 乌尔都语下看过 |
| 旧的设备测试 | `player_device.py`、`media_ui_device.py` 改了，但要媒体服务器和样片，**没有重跑**；`iptv_device.py` 没跑 |
| 真实发送端 | `cast.home` 只看了页面，没有真实手机去投 |
| 安卓 App 里的返回手势 | 本期不做，属 `29` 号文档阶段 4（要 `system/thinkos-shell`） |

## 9. 风险

| 风险 | 对策 |
|---|---|
| 左缘 24dp 内按下的轻点和长按要等到抬手或滑过 slop 才交给页面，那一条上的长按反馈会晚到 | 只在栈非空时才扣；条很窄，操作栏顶缘用的是同一套 |
| 返回预览要建出返回目标页，首次拖动可能卡；目标是时钟页时尤其要紧 | 现在是拖动开始时才建；若实测卡，改成像翻页邻页那样提前 `queuePreview` |
| 嵌套返回栈的边界（崩溃、禁用、设置期间接管、并发打开） | 纯 Kotlin 的 `NavStack` + JVM 测试，设备脚本补集成 |
| 应用拦截返回却不响应 | 2 秒兜底；操作栏和救援手势始终在 |
| Home 键现在也会把正在放的片子的页面清掉（片子本身按 `page.leave` 暂停） | 文档与 ADR 已写明；若觉得不对再改 |
